# Domain Model

## Glossary

### Screenshot
A digital image capture of a web page's visual content, including all rendered HTML, CSS, and JavaScript elements as they appear in a browser viewport.

### Image ID
A unique identifier passed in the URL path for screenshot requests. Currently used for routing purposes but not for actual image lookup or caching.

### Website URL
The target web address to be captured in a screenshot. Must be a valid HTTP/HTTPS URL pointing to an approved Passkey domain.

### Viewport
The visible area of a web page within a browser window, defined by width and height dimensions in pixels. Determines how the page is rendered before screenshot capture.

### Cache Key
A unique identifier used to store and retrieve screenshots from S3 storage, composed of the target website's hostname and pathname (e.g., `demo.passkey.com/hotel-booking`).

### Semaphore
A concurrency control mechanism that limits the number of simultaneous screenshot operations to prevent resource exhaustion and ensure system stability.

### Fallback Image
A pre-generated "unavailable" image returned when screenshot capture fails due to timeouts, errors, or other issues. Ensures clients always receive a valid image response.

### Preview Token
An authentication token used to access preview or staging versions of websites that require special permissions or authentication.

### Force Refresh
A parameter that bypasses the cache and forces generation of a new screenshot, even if a cached version exists.

### Approved Domains
A whitelist of domain suffixes (`.passkey.com`, `.cvent.org`) that are allowed for screenshot capture, enforcing security and preventing abuse.

### Concurrency Limit
The maximum number of screenshot operations that can run simultaneously (default: 3), implemented to prevent system overload and ensure fair resource allocation.

## Core Entities

### ScreenshotRequest
**Description**: Represents a client request for a website screenshot with specific parameters and requirements.

**Attributes**:
- `imageId`: string - URL path parameter for routing
- `websiteUrl`: string - Target website URL to capture
- `viewportWidth`: number - Browser viewport width in pixels
- `viewportHeight`: number - Browser viewport height in pixels
- `screenshotWidth`: number | undefined - Override width for capture
- `screenshotHeight`: number | undefined - Override height for capture
- `forceRefresh`: boolean - Whether to bypass cache
- `previewToken`: string | undefined - Authentication token for preview access

**Relationships**:
- Processed by ScreenshotService
- Validated by RequestUtils
- Results in ScreenshotResponse

### ScreenshotResponse
**Description**: The processed image data returned to the client, including metadata and binary content.

**Attributes**:
- `imageData`: Buffer - Binary JPEG image data
- `contentType`: string - MIME type (always 'image/jpeg')
- `contentLength`: number - Size of image in bytes
- `statusCode`: number - HTTP response status
- `cacheHit`: boolean - Whether image was served from cache

**Relationships**:
- Generated by ScreenshotService
- Processed by ResizeService
- Delivered via Express response

### CachedScreenshot
**Description**: A screenshot stored in S3 cache for future retrieval, indexed by hostname and pathname.

**Attributes**:
- `hostname`: string - Domain name of the captured website
- `pathname`: string - URL path of the captured page
- `bucketName`: string - S3 bucket containing the image
- `imageData`: Buffer - Cached image binary data
- `createdAt`: Date - When the screenshot was captured
- `lastAccessed`: Date - When the cache was last hit

**Relationships**:
- Managed by DBClientService
- Retrieved for ScreenshotRequest processing
- Updated when forceRefresh is used

### BrowserSession
**Description**: A Puppeteer browser page instance used for website navigation and screenshot capture.

**Attributes**:
- `page`: Page - Puppeteer page object
- `viewport`: Viewport - Browser viewport configuration
- `targetUrl`: string - URL being captured
- `loadStartTime`: number - Timestamp when navigation began
- `timeouts`: TimeoutConfig - Timeout settings for various operations

**Relationships**:
- Created by WebScreenshotService
- Controlled by semaphore limits
- Produces screenshot image data

### ImageProcessingJob
**Description**: A task for resizing and optimizing a screenshot image according to client specifications.

**Attributes**:
- `sourceImage`: Buffer - Original screenshot data
- `targetWidth`: number - Desired output width
- `targetHeight`: number - Desired output height
- `format`: string - Output format (always JPEG)
- `quality`: number - Compression quality setting

**Relationships**:
- Processed by ResizeService
- Input from screenshot capture
- Output to ScreenshotResponse

## Business Rules

### Domain Security
- Only websites with domains ending in `.passkey.com` or `.cvent.org` are allowed
- URL validation occurs before any processing begins
- Invalid domains result in immediate 400 Bad Request response

### Caching Strategy
- Screenshots are cached indefinitely until explicitly refreshed
- Cache keys are based solely on hostname and pathname
- Query parameters (except previewToken) do not affect caching
- Force refresh bypasses cache and updates stored image

### Concurrency Management
- Maximum 3 simultaneous screenshot operations allowed
- Requests exceeding limit wait up to 30 seconds for availability
- Timeout results in fallback image rather than error response
- Semaphore ensures fair resource allocation

### Error Handling
- All errors result in valid image responses (never HTTP errors for image requests)
- Fallback images maintain requested dimensions through resizing
- Timeout scenarios are logged but don't interrupt service availability
- Invalid requests return appropriate HTTP error codes

### Image Processing
- All output images are JPEG format regardless of source
- Images are resized to exact requested dimensions
- Aspect ratio may be altered to match specifications
- Quality is optimized for web delivery

### Performance Optimization
- Cache hits return images within 200ms typically
- New screenshots may take 5-15 seconds depending on page complexity
- Browser instances are reused when possible
- Memory usage is controlled through image processing limits

## Data Relationships

### Request Processing Flow
```
ScreenshotRequest → URL Validation → Cache Lookup → BrowserSession → ImageProcessingJob → ScreenshotResponse
```

### Cache Management Flow
```
CachedScreenshot ← S3 Storage ← DBClientService ← ScreenshotService → Cache Lookup
```

### Error Handling Flow
```
Error Condition → Fallback Image → ImageProcessingJob → ScreenshotResponse
```

## State Transitions

### Screenshot Request Lifecycle
1. **Received**: Request arrives with parameters
2. **Validated**: URL and parameters checked for validity
3. **Cache Checked**: Existing screenshot lookup performed
4. **Queued**: Request waits for available browser slot (if needed)
5. **Processing**: Browser captures screenshot
6. **Cached**: New screenshot stored in S3
7. **Processed**: Image resized according to specifications
8. **Delivered**: Final image returned to client

### Cache Entry Lifecycle
1. **Created**: New screenshot stored with hostname/pathname key
2. **Active**: Available for cache hit responses
3. **Refreshed**: Updated when forceRefresh is used
4. **Accessed**: Retrieved for client requests

### Browser Session Lifecycle
1. **Acquired**: Semaphore slot obtained
2. **Initialized**: New page created with viewport settings
3. **Navigating**: Page loads target URL
4. **Loaded**: DOM content and resources loaded
5. **Capturing**: Screenshot operation performed
6. **Completed**: Image data captured
7. **Released**: Page closed and semaphore slot freed

## Integration Points

### External Dependencies
- **AWS S3**: Screenshot cache storage and retrieval
- **Google Chrome**: Browser engine for page rendering
- **Target Websites**: Passkey-hosted hotel and booking sites

### Internal Components
- **Express Server**: HTTP request/response handling
- **Puppeteer**: Browser automation and control
- **Sharp Library**: Image processing and resizing
- **Logging System**: Error tracking and performance monitoring

### Monitoring Integration
- **Datadog**: Performance metrics and error tracking
- **Health Checks**: Service availability monitoring
- **Resource Metrics**: Memory, CPU, and concurrency tracking
