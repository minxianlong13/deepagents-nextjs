# Domain Model

## Glossary

### Bearer Token
A security token used for authentication in the WebSocket connection. The token is validated against an external authentication service to ensure the client has permission to access the credit card verification service.

### Context ID
A unique identifier that represents the context or session of a credit card verification request. This ID is used to track and correlate verification requests across different services in the Passkey ecosystem.

### Connection ID
A unique identifier assigned to each WebSocket connection by API Gateway. Used to route responses back to the correct client connection and track connection-specific metrics.

### Credit Card Verification
The process of validating credit card information in real-time during the hotel booking process. This includes checking card validity, format, and potentially performing authorization checks.

### PBR Survey
Property Booking Request survey - a form presented to potential hotel guests to collect booking information, including credit card details for payment processing.

### Passkey Ledger
The core financial service in the Passkey ecosystem responsible for processing payments, managing transactions, and handling credit card operations.

### WebSocket API
A real-time communication protocol that maintains persistent connections between clients and servers, enabling instant bidirectional communication for credit card verification.

## Core Entities

### Verification Request
**Description**: Represents a credit card verification request initiated by a client

**Attributes**:
- `contextId`: string - Unique context identifier for the verification session
- `bearerToken`: string - Authentication token for the request
- `userId`: string - Identifier of the user requesting verification
- `connectionId`: string - WebSocket connection identifier (auto-generated)

**Relationships**:
- Associated with a WebSocket connection
- Links to user session in authentication service
- Correlates with ledger transaction records

### WebSocket Connection
**Description**: Represents an active WebSocket connection for real-time communication

**Attributes**:
- `connectionId`: string - Unique connection identifier
- `bearerToken`: string - Authentication token used for connection
- `contextId`: string - Associated context for the connection
- `userId`: string - User associated with the connection
- `status`: enum - Connection status (connected, disconnected, error)
- `timestamp`: datetime - Connection establishment time

**Relationships**:
- One-to-many with verification requests
- Associated with authentication token
- Linked to user session

### Authentication Token
**Description**: Security token used for API access and user authentication

**Attributes**:
- `token`: string - The actual bearer token value
- `userId`: string - User ID associated with the token
- `expirationTime`: datetime - Token expiration timestamp
- `scope`: array - Permissions granted by the token
- `isValid`: boolean - Current token validity status

**Relationships**:
- Associated with user identity
- Used by WebSocket connections
- Validated by external auth service

### API Response
**Description**: Standard response format for all API operations

**Attributes**:
- `statusCode`: number - HTTP status code (200, 400, 401, etc.)
- `body`: string - Response body content (JSON stringified)
- `message`: string - Human-readable response message
- `timestamp`: datetime - Response generation time
- `connectionId`: string - Associated connection (for WebSocket responses)

**Relationships**:
- Generated by Lambda functions
- Sent via WebSocket connections
- Logged for monitoring and debugging

### Secrets Configuration
**Description**: Secure configuration values retrieved from AWS Secrets Manager

**Attributes**:
- `apiKey`: string - API key for external service authentication
- `ledgerUrl`: string - Base URL for Passkey Ledger service
- `authUrl`: string - Base URL for authentication service
- `environment`: string - Current deployment environment

**Relationships**:
- Used by Lambda functions for external API calls
- Managed by AWS Secrets Manager
- Environment-specific configurations

## Business Rules

### Authentication Rules
1. **Token Validation**: All WebSocket connections must provide a valid bearer token
2. **Token Expiration**: Expired tokens result in connection denial
3. **Single Use Context**: Each contextId should be unique per verification session
4. **User Association**: Bearer tokens must be associated with a valid userId

### Verification Process Rules
1. **Required Parameters**: contextId, bearerToken, and userId are mandatory for all requests
2. **Connection State**: Verification requests can only be processed on active WebSocket connections
3. **Ledger Integration**: All verification requests must be forwarded to Passkey Ledger service
4. **Response Handling**: All responses must be returned via the originating WebSocket connection

### Security Rules
1. **API Key Protection**: API keys must be retrieved from Secrets Manager at runtime
2. **Token Scope**: Bearer tokens must have appropriate scope for credit card operations
3. **Connection Isolation**: Each WebSocket connection is isolated and cannot access other connections
4. **Audit Logging**: All verification requests and responses must be logged for audit purposes

### Error Handling Rules
1. **Graceful Degradation**: Service should handle external service failures gracefully
2. **Client Notification**: Clients must be notified of verification failures via WebSocket
3. **Retry Logic**: Failed external API calls should be retried with exponential backoff
4. **Connection Cleanup**: Failed connections should be properly cleaned up and logged

### Data Flow Rules
1. **Request Validation**: All incoming requests must be validated before processing
2. **Parameter Extraction**: Query parameters must be extracted and validated from WebSocket events
3. **Response Format**: All responses must follow the standard API response format
4. **Connection Tracking**: Connection IDs must be used to route responses correctly

### Integration Rules
1. **Ledger Dependency**: Service depends on Passkey Ledger for actual credit card processing
2. **Auth Service Dependency**: Token validation requires external authentication service
3. **Service Discovery**: External service URLs must be configurable per environment
4. **API Versioning**: External API calls must specify appropriate version endpoints (/v1/)

## State Transitions

### WebSocket Connection States
```
[Disconnected] → [Connecting] → [Connected] → [Disconnected]
                      ↓              ↓
                 [Auth Failed]   [Processing] → [Response Sent]
```

### Verification Request States
```
[Received] → [Validating] → [Forwarding] → [Processing] → [Complete]
     ↓            ↓             ↓             ↓
[Invalid]    [Auth Failed]  [Service Error] [Timeout]
```

## Domain Events

### Connection Events
- `ConnectionEstablished`: WebSocket connection successfully created
- `ConnectionFailed`: WebSocket connection failed due to authentication
- `ConnectionClosed`: WebSocket connection terminated

### Verification Events
- `VerificationRequested`: Credit card verification request received
- `VerificationForwarded`: Request forwarded to Passkey Ledger
- `VerificationCompleted`: Verification process completed successfully
- `VerificationFailed`: Verification process failed with error

### Security Events
- `TokenValidated`: Bearer token successfully validated
- `TokenRejected`: Bearer token validation failed
- `UnauthorizedAccess`: Attempt to access service without valid token
