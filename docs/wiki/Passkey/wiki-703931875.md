# Token & Verification Details:

-   The magic link will need a verifiable embedded token in the URL. The URL will go to planners.passkey.com/login?accessToken={embeddedToken}. In the PortalPreAuthenticationFilter.java class we will check whether the HTTP request has the accessToken param. If it is null, we go about the regular login state as usual. If accessToken is populated, we will add logic into this class to verify the validity of the token and hit the authentication flow to log the user in.
    -   There are two possible tokens to use, cvent-auth and JWT. The cvent-auth token would be encrypted so we can shrink the URL. We will need to check with Amit if we go with this approach to see if it's okay to have the encrypted cvent-auth token in the URL.   
        -   Cvent-Auth Approach:
            -   Since we are encoding the cvent-auth token in the magic link URL, we will need to decode it and then verify it's validity. The functionality to verify a token already exists.
            -   We need to then get all the planner related info from the cventAuth token and populate the principal object.
            -   Can set custom ttl, default should be 1 day
            -   Could be security concerns? **(Yes, big ones - see my comment, Etienne)**
        -   JWT Approach:
            -   The JWT token will have the plannerId encrypted into it.
            -   Can encrypt the token and payload, and set custom ttl.
            -   Once the token and email address / plannerId has been verified, we can allow the rest of the flow to continue as expected, resulting in the Odyssey landing page or Legacy Planner Portal page
            -   In the event we cannot just validate the token and allow the rest of the filters and providers to do the work we will need to:
                -   When the JWT and planner email have been verified, we will check if the planner has access to Odyssey via the passkey\_odyssey experiment, depending on the result of this check we will create a token and route them to the correct url:
                -   Odyssey Enabled: cvent-auth token and route to app.planners.passkey.com
                -   Odyssey Disabled: JSESSIONID and route to planners.passkey.com
-   TTL on the JWT token needs to be determined.
    -   It seems Cvent standard for this is around 24 hours. If we keep with this, should we have a maximum number of clicks during those 24 hours?
-   If the user account status is expired, inactive, or disabled, they should error out to the Bad State modal.
