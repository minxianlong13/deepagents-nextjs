# Introduction

This document investigates the data structures in Passkey's backend used for managing taxes and fees at an event and hotel level.

# Database Schema:

  

## Table Descriptions

EventProfile.HotelTaxStructure stores the business text keys for the disclaimer and the participantId/EventId. Hotel-level taxes will have a null eventId.

  
EventProfile.HotelTaxAndFees stores the actual monetary details about the specific tax rate.

-   AmountValue: The number value used in the calculation based on the next fields 
-   CalculatedFromTypeId: Currently 2 values exist. Flat rate and Night rate. 
-   CollectionScheduleTypeId: Currently 3 values exist. Per guest, Per room, Per night. 
-   HotelTaxAmountTypeId: Currently two values exist. Amount or Percentage 

  

Look up tables for the above Id's

-   EventProfile.HotelTaxCalculatedFromType
-   EventProfile.HotelTaxCollectionScheduleType
-   EventProfile.HotelTaxAmountType

  

**\*\*NOTE THESE ARE ALREADY INCLUDED IN THE ROOM RATE SO NOTHING NEEDS TO BE DONE WITH THESE FOR PHASE 1\*\***

EventProfile.Block and EventProfile.RoomType (Block and Room level) allows the setting of a fee based on the amount of guests added to a reservation. There are columns on both tables called AddPersonCharge, RoomRate3rd, RoomRate4th, RoomRate5thPlus that would get added to the base roomRate. In Passkey-Book this currently isn't broken down to show the additional guest fee. It just looks like a higher base room rate.

## Back End Strategy Phase 1

Database:

A new column was added to the hotel tax and fee table call rateInclusionType. It can either be INCLUDE\_IN\_DISPLAY\_RATE or EXCLUDE\_FROM\_DISPLAY\_RATE.

  

Microservice: 

Create or update an existing one to allow fetching of needed tax/fees at the hotel/event level.

Create an endpoint supporting the saving/updating of taxes and fees including the new column above. Needs to support event and hotel level. 

# Code Change Overview:

## Key files to be aware of – Java Side:

-   ReservationServiceImpl.java → Responsible for calculate values for running total. Most important on the Java side.
-   HotelListController.java → Generally the first controller to be hit when a user makes a reservation. Responsible for fetching the rates to show to a user on the hotel page.
-   RoomListController.java → After a user selects a hotel, they are shown the rooms available for reservation under that hotel. This will refetch the rates.
-   SelectRoomController.java → This controller is repsonsible for upgrade stay, addon selection, and extend stay. Addons have not changed. Upgrade stay and Extend Stay have been changed to reflect the rates.
-   GuestInfoController.java → This controller is where a user will supply their guest information (PII + Credit Card/Billing Information). Relatively unchanged.
-   SummaryController.java → This controller is the final page before the user confirms their reservation. The resAggergate is updated for the rates.

## Key files to be aware of – Javascript and Java Servlet Pages Side: 

Keep in mind, there are both mobile and desktop versions. The namings of these jsps and js files are usually self-explanatory, so I won't list all the files here.

-   quickbook.js → Generally responsible for the running total. Most important on the Javascript side.
-   hotel-list.jsp → Shows the hotels
-   room-list.jsp → Shows the rooms
-   res-summary.jsp (modern + groupBooking) → Pre-confirmation page
-   summary-booking-mh.jsp (multi hotel group booking page) → Post-confirmation page
-   summary-booking.jsp (group booking) → Post-confirmation page
-   summary.jsp → single/multi-room pre-confirmation page
-   res-summary.jsp → single/multi-room post-confirmation page
