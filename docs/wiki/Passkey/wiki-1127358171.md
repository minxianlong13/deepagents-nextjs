1Impersonation Mode Overview

## Overview

Impersonation Mode allows a user in Resdesk or RDK2 to “walk into” the Planner Portal (Odyssey) as a planner or SBG contact, in order to see what they see and troubleshoot issues more effectively, while enforcing strict read-only and safety constraints inside the Planner Portal.

This bug bash is focused on validating:

-   Entry into Impersonation Mode from Resdesk and RDK2
-   The Planner Portal experience while impersonating (banner, navigation restrictions, disabled actions)
-   That users cannot perform disallowed actions or escape the restricted experience
-   That existing non-impersonated behavior is not regressed

## Goals

-   Confirm that Resdesk and RDK2 correctly generate and honour impersonation entry URLs/tokens for both “View Portal as Planner” and “View Portal as SBG Contact” entry points.
-   Validate that the Planner Portal clearly indicates when a user is in Impersonation Mode and provides a reliable way to exit back out.
-   Ensure that navigation and key actions are restricted as designed (locked side navigation items, disabled inventory/rates views, disabled account management, etc.).
-   Identify UX gaps, confusing flows, and any mismatches between the Developer Audit / mocks and the implemented behavior.
-   Capture edge cases and regressions compared to logging directly into the Planner Portal as the same user.

  

2What's new?

### End-to-end flow

-   Users can be walked directly into the Planner Portal from **Resdesk** or **RDK2** instead of logging in separately, using an impersonation entry URL/token.
-   Resdesk and RDK2 frontends are updated so that existing actions are now triggered via the SBG Contact/Planner **hamburger menu**, and these actions generate the impersonation entry URL/token when launching the Planner Portal.

### Planner Portal (Odyssey) behaviour in Impersonation Mode

-   An **app-level impersonation banner** is shown, indicating that the user is viewing the event as a different user, and providing an **Exit** action.
-   A context flag for “impersonation mode” drives conditional behavior in components (e.g., what nav items are enabled/disabled, which actions are blocked).
-   The **Home button** is hidden in impersonation, and clicking the **Cvent logo** must no longer navigate back to the event list. Any alternative routes that take you home/event list should either be disabled or intentionally handled.
-   The left **side navigation** is restricted:
    -   All entries except **Event Overview** are shown as **locked** and disabled during impersonation.
    -   Deep-linking into locked pages should be prevented; users should either be redirected to a safe page (e.g., Event Overview) or see a clear “forbidden” treatment.
-   Certain high-risk actions are disabled:
    -   **View All Inventory and Rates** link is locked and non-clickable.
    -   **Manage Account** modal is removed in impersonation.
    -   **Unconfirmed Reservations Alert** - Review reservations link
    -   **Room Night Summary Chart** - Run Block and Pickup Report link
    -   **Booking Pace Chart** - Compare Events link

Use this context while testing, but treat details that appear ambiguous in the design (e.g., tooltip text, specific deep-link behaviour) as areas to probe and file feedback on.

6Scope

### In Scope

-   **Resdesk**
    
    -   New hamburger menu behaviour for event planner actions.
    -   “View Portal as Planner” entry into impersonation, including token/URL generation.
-   **RDK2**
    
    -   New menu entry for SBG contact actions hamburger menu.
    -   “View Portal as SBG Contact” entry into impersonation.
-   **Planner Portal (Odyssey)** in **Impersonation Mode**
    
    -   Impersonation banner visibility, copy, and behaviour of the **Exit** control.
    -   Hiding of **Home** button and behaviour of the **Cvent logo** (must not navigate to event list).
    -   Side navigation behaviour when impersonating:
        -   Only **Event Overview** should be accessible.
        -   All other nav entries should appear locked and be non-clickable.
    -   Deep-link handling:
        -   Direct links into pages that should be locked must not allow access; user should get a clear restricted behaviour (redirect to Event Overview or explicit forbidden state).
    -   Disabled features:
        -   **View All Inventory and Rates (All Charts)** link locked and non-clickable.
        -   **Manage Account** modal not accessible during impersonation.
        -   **Unconfirmed Reservations Alert** - Review reservations link
        -   **Room Night Summary Chart** - Run Block and Pickup Report link
        -   **Booking Pace Chart** - Compare Events link

### Out of Scope (for this Session)

-   Performance / load testing (only note egregious performance issues).
-   Back-end implementation details that don’t surface as user-facing bugs.
-   Non-impersonated Planner Portal flows, except for quick regression checks around changed components (banner, nav, entry points).

  

6Testing Scenarios

### 1. Entry into Impersonation Mode

**Resdesk – View Portal as Planner**

-   From Resdesk, use the updated hamburger menu to choose “View Portal as Planner”.
-   Confirm the planner portal opens and:
    -   You see the impersonation banner.
    -   You land on the expected event view.
    -   URL contains a token or structure that indicates an impersonation session.
-   Try multiple planners and events:
    -   Event with simple setup.
    -   Event with multiple planners.
    -   Events where planner may have limited or read-only permissions.
    -   Copied Event planner
    -   Planner with no account setup
    -   Different account types - Hotel / Org / SpOrg / Passkey

**RDK2 – View Portal as SBG Contact**

-   From RDK2 SBG contact screen, use the updated hamburger menu to choose “View Portal as SBG Contact”.
-   Confirm similar behaviour as above:
    -   Banner is present.
    -   Event context is correct.
    -   Nav and restrictions match expectations for impersonation.
-   Try multiple SBG variants:  
    -   SBG with Contact from Library
    -   New SBG with new Contact
    -   SBG with multiple Contacts
    -   SBG with Contact from PBR flow
    -   _SBG with Contact from Autoblock_
    -   Different account types - Hotel / Org / SpOrg / Passkey

**Negative / Edge Cases**

-   Attempt entry for past events and ensure behaviour is consistent.
-   Try to re-use an impersonation URL after exiting or after session timeout.

* * *

### 2\. Impersonation Mode Banner & Exit Behavior

-   Verify the **banner** clearly states that the user is viewing the event as another user.
-   Verify presence and behavior of the **Exit** action:
    -   Does the tab close when you click Exit?
    -   Does it behave consistently across browsers and from different entry points?
-   Confirm the **banner persists**:
    -   Across navigation within the event overview
    -   After refresh.
-   Check if any **tooltips or help text** are provided explaining why certain items are disabled.

* * *

### 3\. Navigation Restrictions

**Side Navigation**

-   Confirm that only **Event Overview** is clickable in Impersonation Mode.
-   All other nav entries:
    -   Appear disabled (e.g., dimmed) and show a **lock icon**.
    -   Do not respond to clicks.
-   Verify for both planner and SBG impersonation.
-   Verify the correct side-nav options are displayed as expected for the Contact/Planner

**Deep Linking**

-   Paste URLs to:
    -   Event List.
    -   Hotels and Inventory
    -   Reservations
    -   Room Lists
    -   Booking Website
    -   Event Alert Settings
-   When in impersonation mode, verify:
    -   You cannot access restricted pages.
    -   Behaviour is consistent (redirect vs forbidden vs error).
    -   Error or redirect messaging is clear and intentional.

* * *

### 4\. Restricted Features / Actions

**View All Inventory and Rates / Block and Pickup Report / Compare Events**

-   Locate the “View All Inventory and Rates”, "Block and Pickup Report" and "Compare Events" link
-   Ensure link shows as ldisabled.

**Manage Account Modal**

-   Confirm the button is visible but disabled.

**Cvent Logo**

-   Clicking the Cvent Logo should no longer navigate the user to the Event List page

**Event List Breadcrumb**

-   Link to Event List is disabled

**Home Icon**

-   Button is hidden and no longer interact-able

* * *

### 5\. Regression / Usability Checks

-   Start a **non-impersonated** session in Planner Portal:
    -   Confirm the Home button and Cvent logo behave as before.
    -   Confirm all side nav items and restricted features work normally when not impersonating.
-   Validate that the impersonation banner, locks, and restrictions **only** appear during impersonation and not for standard planner logins.
-   Check for:
    -   Broken styling.
    -   Misaligned icons.
    -   Confusing or missing hover states.

### 6\. Edge Case Scenarios

-   Login with 2 separate organizers that are affiliated with the same event and view the same planner at the same time
-   Login with a planner and impersonate the same planner at the same time
