## **Business Reasons/Goals**

* * *

A messaging tool can be valuable within a platform like Passkey to drive more collaboration amongst the people managing the event and room block.  It helps:

1.  Centralize and organize communication amongst 2 people, or a team of people, working together to reach an end goal
2.  Increase transparency and history around things discussed related to the event
3.  Other know who to even reach out to or connect with / leads to quicker action and decision making 

By delivering messaging capabilities, we can help our planners, SBG contacts, our event owners (Ex: direct org, TPP, housing company, CVB, hotel personas) or possibly any combination of these users all connect easily and more efficiently during the event management process.   

While we develop our messaging plan, we need to keep in mind one of our primary goals in the delivery of this functionality: 

**Sunset Legacy V1 Dashboard**

Roche currently uses functionality within their Planner Portal experience called **Bulletin Board.**  From a single event, Bulletin Board allows Planner Portal users to create a new, simple open text message, that is sent via email to Event organizers (or other planner portal users).  The messages are stored off of that event record, so you can see who sent, at what time, and what the message is.  

Being able to collaborate with your organizers about the event can keep conversations in context and in an easy informal format.  This can create alignment, improve efficiencies, and it ends up creating a single, searchable record of all communication.  Recording of the messaging ensures accountability, mitigates risks by preventing misunderstandings, and provides a transparent, traceable audit trail for future.  All hopefully leading to driving better user experience and higher engagement on an event.  

So what's the problem with what we have today? 

1.  For one, this functionality that offers in-house collaboration is outdated and only currently available for 1 customer on our platform (Roche) 
2.  Feedback that has been given about the current workflow: 
    1.  The notification system for the organizer is poor and consists of an email that doesn't show the full message
    2.  You can NOT reply to the email to post a message, but have to come back to the dashboard to keep the thread alive
    3.  When SBG contact posts, the recipients they chose get an email but you can't see full message and can't actually reply to the message.  Often accidentally reply and then this bounces back.
    4.  If a message is posted for all users, some users don't get an email. 
    5.  Formatting is available but not used

So the key is how can we build a go-forward communication tooling that Roche will find acceptable to meet their business needs and move to our new planner portal, **and** also make the new feature appealing and valuable for more portal users to want to adopt?

## **Discovery - Workflows and Visuals** 

* * *

My meetings platform has the roles of an admin, an event stakeholder, and a sub-block stakeholder (which is the same role as the event stakeholder, with just limited view into a portion of the event).

These three roles all need to work together to manage an event (aka meeting) and the room reservations associated with that meeting. And sometimes they need to be able to message one another, and I need to show how all three are able to interact with one another. Let's say one event has an admin assigned to it with visibility to 2 different room blocks (one for staff at the Marriott, 1 for general attendees at the Marriott, and 1 for general attendees at the Hilton). The 1 event stakeholder is assigned to the same thing the admin sees. Then the 2 sub-block stakeholders each see limited visibility. First sub-block stakeholder is assigned to just the staff block at the Marriott, and the other sub-block stakeholder is assigned to general attendees at both hotels). My messaging system needs to allow for folks to interact with one another. I want to show that the admin can message the event stakeholder one message privately. Then I want to show the event owner can message all event and sub-block stakeholders the same message. Then show 1 sub-block stakeholder replying back to the event owner (but the others can't see). Then show the sub-block stakeholders messaging each other only. Lastly show the sub-block stakeholder who represents the general session attendees sending a message to the event stakeholder and the event admin. Then show them each replying back separately on a thread to the sub-block stakeholder. Neither the event admin or the event stakeholder can see each other's replies to the message sent by the sub-block stakeholder.

1.  Are we okay with admins not seeing every message and/or every reply? 
2.  Even if someone is part of a sub-block, does that mean they shouldn't be able to communicate with someone outside of sub-blocks they have access to for the event?  
3.  Is any visibility determined by which hotels you have access to?  If someone is messaging about the Hilton hotel, does that automatically mean that sub-block stakeholder wouldn't be someone you could message?
