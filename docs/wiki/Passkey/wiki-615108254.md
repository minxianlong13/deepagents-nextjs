RDK2 now ships with instrumentation endpoints that allow you to perform some in-place profiling in most pre-prod environments.  _Instrumentation is not available in prod or intg_.

The instrumentation suite provides you with 3 important endpoints that allow you to collect run-time memory snapshots from NodeJS.

These endpoints are built into RDK2, but can be copy/pasted into any NextJS-driven BFF application.

# Before You Begin Profiling

You need to be aware that the new endpoints documented below 'stop the world' in order to allow you to perform these diagnostic tasks.  In one case in particular (Snapshot create), this can cause your target group health checks to fire a SIGKILL if it does not get heart beat responses for more than 30 seconds or so.  If you encounter this, you may need to reconfigure your target group:

-   By default, 2 failed health checks cause a server restart. The following settings may need to be changed:
-   From AWS Console -> ECS -> <YOUR ECS CLUSTER>:
    -   Click on your service in the services list
    -   Click on the 'target group' name along the bottom of the 'Status' section
    -   In your target group, click on the 'Health Checks' tab, then the 'Edit' button
    -   Click 'Advanced Health Check Settings'
    -   Adjust 'Unhealthy Threshold' to 10
    -   Adjust 'Timeout' to 5 seconds
    -   Adjust 'Interval' to 60 seconds

# How to Collect A Proper Snapshot for Memory Leak troubleshooting

1.  Deploy your service to a controlled, lower environment where load testing is possible.
2.  Run small load test portion to initialize primary constructs (One-time bootstrap initializations)
3.  Wait ~1min for executions to finish.
4.  Execute manual GC (See API below) to remove any ready-to-clean young gen objects (Best to give it 30 sec or so.)
5.  Run a suitable portion of your load test to reproduce memory leak.
    1.  Note: You do not require 10s of MBs of leak in order to diagnose.  Run until you notice the leak, and that should be enough.
6.  Stop your load once you've noticed the leak in Datadog APM's Heap Use dashboard.
7.  Wait ~1min for executions to finish.
8.  Execute manual GC _again_ to remove any ready-to-clean young gen objects (give it 30 secs or so)
9.  Create a snapshot (See API below).
    1.  Snapshot creation may take several minutes.  Monitor Datadog for log message indicating snapshot is complete before attempting to download.
    2.  Also, note that snapshot creation is a stop-the-world event.  Your service will stop responding to other requests while snapshot is being created.
10.  Download the snapshot (See API below).

# Endpoint Overview

The following endpoints are now available 

## Endpoint to perform manual full mark sweep garbage collection of old gen

Allows you to instruct NodeJS to perform a manual full garbage collection.

**Endpoint**: GET http://<RDK2\_ADDR\[:3000\]>/api/gc

**Authentication**: API Key (Via usual Authorization Header)

**Response**: Application/json + HTTP 200 (Ok)

**Example Use**:

Perform GC

  

## Endpoint to perform Snapshot creation

Allows you to instruct NodeJS to create a memory snapshot.

**Endpoint**: POST http://<RDK2\_ADDR\[:3000\]>/api/heap

**Authentication**: API Key (Via usual Authorization Header)

Response: Application/json + HTTP 200 (Ok)

**Example Use**:

Perform Snapshot Create

  

## Endpoint to perform Snapshot fetch

This endpoint allows you to download a previously-generated heap file. Heap files are identified by ID, which is provided to you in the 'create heap' response JSON payload.

**Endpoint**: GET http://<RDK2\_ADDR\[:3000\]>/api/heap?fileId=1234567

**Authentication**: API Key (Via usual Authorization Header)

Response: Application/octet-stream + HTTP 200 (Ok)

**Example Use**:

Perform Snapshot Create
