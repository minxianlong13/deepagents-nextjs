# Overview

The Autoblock provisioned block request saga may fail if one of the steps fails during implementation. This would lead to a corrupted state of Block, SubBlockGroup, or Event. In order to bring all systems to the correct state after a failure, Autoblock Saga needs to implement a rollback flow that will contain one rollback step per saga state, except the creation planner. Created or updated planners can stay in the system without any impact or corruption on the system. Moreover, we can reuse the planner entity in the next invocations.

# Business Rules

1.  This is the technical part of Saga implementation so not a lot of business rules but one of the main drivers is that all compensating transactions (steps) must be extracted in separate lambda functions because Autoblock Manual approval's Decline Saga is going to reuse them in decline flow that will mimic rollback with caveat to master status.
2.  We don't need to track and update planner PII or remove planner from the system as a part of rollback because the created entity can and will be reused in any other provisioned requests. (Needs Product team approval)
