# **2) Docker Overview**

      Docker creates a container where actual program/application will run. It creates another layer of abstraction between program/application  and your computer and resources used

from your computer. Aim is to gather all relevant executables , resource, os commands, deployable artifacts and programs that executes these artifacts into one place so that this unit, container,

became independent from you actual machine and it is resource, hence as long as the unit is in good shape it can run in any environment and machine.

There are 2 basic component of Docker in a simple development environment. Images and instances.

## **a) Images**

Docker images are blueprints of instances, they create baselines for instances. Very different instances could be created from same image although they are still bound to underlying image. Their relation is similar to 

class and object relationship in Java. Images can be created by 2 ways.

1.  Buildinf from dockerfiles by  "docker build .... -f Dockerfle.xyz ./" which gives you flexibility to create your custom images 
2.  You can basically pull bunch of already ready , just like java library, already on internet which should be the first choice for most of the things  
    command "docker search java8 || kafka || tomcat " will return a lot of images most of which could be used out of the boxes.Then "docker pull <image-name> simply downloads  
    that image from internet and prepare to be used.

"docker images" will list your existing images and "docker rmi  image\_name " will delete image.

## **b) Instances**

Docker instances are running images. All running instance could be seen by "docker ps" , to see stopped instances "docker ps -a ". Docker instances could be stopped and started by 

"docker stop <instance-name>" and "docker start <instance-name>" respectively. It is better to note that images names and instance names are different concepts To create an instance,

use  following template: "docker run --name <instance\_name>  -p <host\_port>:<container\_port> -v <local\_path>:<container\_path> <repo\_name>:<tag>". Basically your host machine port and volumes(paths) can be

matched to your container ports and volumes, so that you don't have to arrange ports or execute another docker command to check logs/files, etc or copy files from host to container every time.
