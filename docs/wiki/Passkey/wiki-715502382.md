<h1>Overview</h1><p>Epic: <ac:structured-macro ac:name="jira" ac:schema-version="1" ac:macro-id="5fb05467-8dab-4e21-aa76-6af9b8ef544b"><ac:parameter ac:name="server">Cvent JIRA</ac:parameter><ac:parameter ac:name="columnIds">issuekey,summary,issuetype,created,updated,duedate,assignee,reporter,priority,status,resolution</ac:parameter><ac:parameter ac:name="columns">key,summary,type,created,updated,due,assignee,reporter,priority,status,resolution</ac:parameter><ac:parameter ac:name="serverId">d1d78885-1a8e-3259-b68d-3df198ee3d46</ac:parameter><ac:parameter ac:name="key">GROUP-105945</ac:parameter></ac:structured-macro></p><p>The Create Event from Roomlist use cases will require an API that will be able to, based on various inputs, generate a new HD event that is automatically pre-provisioned with block, subblock, SBG, attendee, planner and acknowledgement campaign infrastructure so that reservation data can be processed <em>automatically</em> (following event creation) as part of the same workflow.</p><p>This API represents the final action in the final stage of user engagement in the use case.  This API is what is called when the Hotel user hits the &quot;Finish&quot; button to actually perform the event create action. It is assumed that before this stage in the workflow:</p><ul style="list-style-type: square;"><li>All validation of user input has been done, automatically and/or manually.</li><li>An authorized Passkey user representing the Hotel in question has accepted and approved the request.</li><li>All measures of compatibility between the end user's room list request and the actual logical constraints of the hotel have been:<ul style="list-style-type: square;"><li>Assessed and deemed good-to-go as-is</li><li>Assessed and automatically transformed to compatible input(s)</li><li>Assessed and manually transformed to compatible input(s)</li><li>Assessed with no acceptable transformation, and removed from the request</li></ul></li><li>All auto-detected, default and overridable settings/preferences have been confirmed and settled.</li></ul><p><br /></p><p>This design, then, is intended to cover only the final piece of the whole 'Create Event from Roomlist' use case.</p><p><ac:image ac:height="400"><ri:attachment ri:filename="Screenshot 2024-08-27 at 4.23.37 PM.png" /></ac:image></p><h1>API Input Contract</h1><p>As we are not building this API with external contract dependencies, we will not have an official <em>contract requirements</em> phase for this workflow. the building block contracts for creating an event, autoprovisioning, and creating reservations.  Stitched together, they will serve as the initial input contract.</p><p>It will be beneficial, however, to document the contract semantics in order to improve the integration experience when the time comes to merge this API with the User Interface(s) that will drive it.</p><p>The working
