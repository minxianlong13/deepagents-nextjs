# Context

This page shows the results of a performance test on event-name search. The test compared two search strategies. The goal is to match a Passkey event to an event from an external system. The names may differ by typos, word order, or stop words.

Two search modes back two different UI flows:

-   **Type 1 - Contains:** finds an exact word anywhere in the event name. The system uses this first because it is faster.
-   **Type 2 - Fuzzy:** uses word-level Jaro-Winkler (JW) similarity. Word order does not matter. The system uses this if Type 1 returns no results.

Stop words (the, and, a, an, of, for, with, and &) are stripped from the search phrase before the system builds a query. If all words in the phrase are stop words, the system does not send a query to the database.

# Data Model

Event names are in `EVENTPROFILE.PARTICIPANT.NAME` (VARCHAR2 80) where `OBJECTTYPEID = 104`. Dates and status are in `EVENTPROFILE.EVENTINFO`. The column `PARTICIPANT_EVENTS.IS_OWNER = 1` links an event to its owner.

Two indexes exist on `PARTICIPANT.NAME`:

-   `IX_PARTNAME` - B-tree on UPPER(NAME)
-   `IX_PART_NAME_FULL_TEXT` - Oracle Text CONTEXT index (supports CONTAINS())

# Stop Word Handling

Oracle Text `CONTAINS()` drops stop words automatically with its DEFAULT\_STOPLIST. The words the, and, a, an, of, for, with, and & each return zero hits when used alone. For the LIKE and UTL\_MATCH strategies, the application must strip stop words before it builds the query.

# Test Corpus

Tests ran on **sg50 (staging)**. No production data was accessed.

The corpus holds 1,423 open events in a fixed window (2026-01-01 to 2033-12-31). The corpus has two owner groups. Connections Housing (owner id 14227) gives 10 events with real names. Passkeytest221\_Perf\_IBK (owner id 50235773) gives 1,413 Gatling bulk events as noise.

# Recommended Approach

-   **Type 1:** Use Oracle Text CONTAINS with brace-quoted tokens ({token1} AND {token2}). Strip stop words before the query. Typical cost is 34-111 ms.
-   **Type 2:** Use UTL\_MATCH.JARO\_WINKLER\_SIMILARITY with a word tokeniser. Strip stop words before the query. All tokens must score 85 or above. Typical cost is 530-631 ms at 1,423 events.
-   **Fallback for Type 1:** If the Oracle Text index is not available or is out of date, use LIKE. Typical cost is 521-614 ms.

# Caveats

-   The Oracle Text CONTEXT index (IX\_PART\_NAME\_FULL\_TEXT) requires periodic sync. New events may not appear until the next CTX\_DDL.SYNC\_INDEX run. Confirm the sync schedule with the DBA team.
-   Oracle Text fuzzy variants (fuzzy(), ?word) are not benchmarked. The sg50 corpus has too few unique tokens for a valid result. Run the benchmark on a prod-refreshed environment before you use these as a Type 2 alternative.
-   The JW threshold of 85 came from the test cases. Expose it as a configuration property.
-   Validate UTL\_MATCH timing on ct50 (prod-refreshed) against a real large-customer corpus before go-live.
