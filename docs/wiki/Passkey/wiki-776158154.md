internal representation.</p><p>By providing a consistent schema and format, the EMO simplifies integrations, reduces data transformation complexity, and ensures that data can be seamlessly passed through the Passkey ecosystem for:</p><ul style="list-style-type: square;"><li>event creation</li><li>registration linking</li><li>and inventory management.</li></ul><p>This wiki is an output from <ac:structured-macro ac:name="jira" ac:schema-version="1" ac:macro-id="10a70980-075f-410f-8acb-97e8cdb192fa"><ac:parameter ac:name="server">Cvent JIRA</ac:parameter><ac:parameter Scope</h3><h4><strong>Purpose:</strong></h4><ul><li>Define a formal contract (schema) that represents all necessary event data (and related resources) to create and provision an event in the Passkey ecosystem.</li><li>Open the door to support multiple external input formats <em><strong>(CSV, XLS,</strong><strong> PDF, etc.insially will rely on XLS only</strong></em>)  by normalizing them into a single, consistent JSON structure.</li><li>Facilitate transformations needed for public APIs, making it easier to integrate with third-party systems.</li></ul><h4><strong>Scope:</strong></h4><ul><li>The EMO will initially focus on room list-based event creation scenarios.</li><li>In future phases, the EMO can be extended to other request types <u><em>(e.g., GML requests, RFP, RFQ).</em></u></li><li>The specification includes both a JSON schema and a corresponding GraphQL schema definition to ensure compatibility with Apollo/GraphQL-based services.</li></ul><h3>Terminology</h3><ul><li><strong>EMO (Event Metadata Object):</strong> A JSON object encapsulating all the data required to create and provision an event.</li><li><strong>RLM (Room List Mapping):</strong> A service and data model that maps raw uploaded file data (e.g. XLS columns) to normalized EMO fields.</li><li><strong>DynamoDB Mappings Store:</strong> A persistence layer for field mappings generated from raw input files.</li><li><strong>Raw Data Resource:</strong> The original, customer-provided Excel file (e.g., XLS, CSV, XLSX), stored in S3 or via the Cvent File Upload service.</li><li><strong>Passkey-Reglink:</strong> A service that can create events and associated resources. The EMO will be integrated into this workflow.</li></ul><h3>High-Level Architecture</h3><ol><li><strong>Raw Input File (EXCEL):</strong> Customer uploads a room list or other data file.</li><li><strong>RLM Service:</strong> Automatically analyzes the file, identifies column-to-field mappings, and stores the resulting mapping metadata in DynamoDB.</li><li><strong>EMO Generation:</strong> Using the stored mappings and raw file data, the RLM service (or a dedicated EMO service) constructs a JSON-based EMO.</li><li><strong>Integration with Passkey-Reglink:</strong> The EMO is then passed to the passkey-reglink service, which consumes the EMO to create the event, attendee types, room blocks, and other necessary resources.</li></ol><h3>Key Components of the EMO</h3><ul><li><strong>Event-Level Data:</strong> Basic event properties (e.g., event name, start/end dates, venue details).</li><li><strong>Room Block Information:</strong> Information about room types, inventory, and block allocations derived from the parsed input file.</li><li><strong>Attendee Data (Optional):</strong> Potential attendee types or other event participants, if provided.</li><li><strong>Mappings &amp; Normalizations:</strong> Metadata about how raw fields map to normalized EMO fields.</li></ul><p><strong>Example:</strong></p><ul><li><code>eventId</code>: The internal Passkey event identifier that will be assigned after the event is created.</li><li><code>rawFileId</code>: The identifier of the source data file from S3 or the file upload service.</li><li><code>mappings</code>: A structured list of fields mapping raw columns to EMO attributes.</li></ul><h3>JSON Schema </h3><p>in below table , I will try to explore different approaches and highlight the full schema, and the per-minimal starting point schema that we could use as EMO for current RoomList uplaod to create Event. </p><table class="wrapped"><colgroup><col /><col /><col /></colgroup><tbody><tr><th scope="col">schema type</th><th scope="col">reference</th><th scope="col">schema/body details</th></tr><tr><td><h4>initiated Full Schema</h4></td><td><p>This schema is based on reglink ( <a href="https://stash.cvent.net/projects/PA/repos/passkey-reglink/browse/passkey-reglink-api/src/main/java/com/cvent/passkey/reglink/model/roomblock/RoomBlockRequest.java">RoomBlock Request</a>) as well as anticipated object from requirements . </p><p><em>Note: This is a conceptual example. <br />...This Schema will grow as we go with the implementation of Event Creation by RLM list tickets ...</em></p></td><td><div class="content-wrapper"><ac:structured-macro ac:name="code" ac:schema-version="1" ac:macro-id="5b4744a3-412c-4c58-9232-3f937ad5e945"><ac:parameter ac:name="title">Full Schema with detailed objects </ac:parameter><ac:parameter ac:name="collapse">true</ac:parameter><ac:plain-text-body><![CDATA[{
