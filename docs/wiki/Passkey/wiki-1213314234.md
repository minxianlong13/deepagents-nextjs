It sets<span> </span><code>groupByKeys = [month_year, product_feature_code]</code>, which switches<span> </span><code>UsageSummaryDAOMapper.xml</code><span> </span>into its grouped mode: Postgres computes<span> </span><code>SUM(count) … GROUP BY month, account_id, product_feature_code</code><span> </span>and returns<span> </span><strong>one row per feature per month</strong>. Worst case for a 12-month range: 12 × 4 = 48 rows — one page (limit 2000). The tool still loops<span> </span><code>offset += pageSize</code><span> </span>until a short page arrives (defensive, cheap), then folds the monthly rows into per-feature totals in memory and returns them in one response. The monthly rows are kept as<span> </span><code>monthlyBreakdown</code><span> </span>so 6–12 month questions get a trend for free. Consolidation happens in the tool; the client receives a single, complete answer.</p><hr style="" /><h2 style="">Tool contract</h2><pre><code>name:        get_feature_wise_usage
