# Overview

The magic link login to Passkey Autoblock request website flow allows extending access to auto-provisioned requests to the public with just entered email. Based on entered email Passkey service side will decide if the user exists (by extRecipientId) or is a new user. In the case of a new user, the service side will create extRecipientId and send a request for a magic link to Universal login.

# User scenario

`Given an organizer`

`And an event with enabled Autoblock`

`And an autoblock wizard configuration`

`And a Publick User`

`When the organizer shares Autoblcok request site access link`

`Then the Publick User navigates to the public link`

`And Publick User enters owned email address`

`And Publick User validates reCaptcha check`

`And Publick User clicks the access button`

`Then Publick User gets a notification message about the magic link has been sent to their email`

`When Publick User opens up owned email (over supported email client)`

`Then Publick User gets the magic link in the email body from Okta`

`And Publick User navigates to the magic link`

`When Okta builds up request navigation link`

`Then Publick User can have access to Autoblock Request website.`
