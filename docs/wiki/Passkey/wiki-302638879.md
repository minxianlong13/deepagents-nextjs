# Introduction

CallBack is the way to notify the registration provider on own events, typically on reservation changes such as creating a reservation, modifying it, or cancelling it.

# Objectives

Integrate callback as parallel lambda in passkey reservation-saga CDK.

# Rules

-   Allow to complete reservation flow regardless of callback success or failure. In other words failure of callback should not prevent create/modify/cancel reservation.
-   Allow parallel execution of callback, as separate step in passkey reservation-saga, parallel to sending acknowledgment. Call to callback should happen as one of the last steps of reservation-saga parallel with acknowledgement. This way will allow us to not perform roll back.

# Reservation-saga function gaps

Need to introduce CallBack lambda and integrate it with create/modify/Cancel flow. CallBack lambda will be executed in parallel with SendAck lambda and its output will be written into TaskLog of ReservationLogger. Any failure in CallBack lambda will be written into TaskLog and StatusLog of ReservationLogger. The callback call will happen in lambda so we can capture exception in case if it happens and fail to fail step with email to send if any.

# StatusLog

During reservation created/updated/cancel, any failure in CallBack lambda, StatusLog in DynamoDB will contain an error in errorMessage column. On call to get reservation status, reservation status will be return with parsed details information from errorMessage column if any exists. This way we will report back to end user current status of reservation with CallBack error. Note: errorMessage will store an array of errors, this will allow to accumulate any errors that happen during reservation flow.
