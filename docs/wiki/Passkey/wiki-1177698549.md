This document specifies the Room Block Bridge Page — a new neighborhood destination on every Cvent Event that surfaces room block status, enables linkage, and provides access into Passkey — without requiring planners to abandon their event context. Epic 1 is scoped to Passkey license holders only. It establishes the foundational bridge page experience that Epic 2 will extend to hotel-owned and TPP-managed room blocks.</p><h2>Problem Statement</h2><p>Cvent customers hold licenses across Event Management and Passkey, but the two products operate as disconnected silos. Planners must context-switch between applications to understand room block and reservation details for their upcoming event. This friction reduces adoption of both products and obscures the value of Cvent's combined platform.</p><p><strong>Three specific gaps this epic closes: </strong></p><p>▸ No navigation pathway from a Core Event into a specific Passkey room block</p><p>▸ No room block metrics visible from the Event — planners must log into Passkey to check pickup.</p><p>▸ Linking a room block to event registration requires multiple manual steps across two applications</p><ul><li data-uuid="589b04ee-786f-4cb8-92d6-b3ce96ab79dd">This epic will address reducing multiple steps when linking passkey site to event reg from bridge page</li><li data-uuid="b98fedda-459c-4ff9-b419-1f15a2254999">This epic will not address reducing multiple steps when user is linking first from Travel module, but it will set the groundwork and unblock Travel team from doing so in future work</li></ul><h2>GTM Milestone 1 Scope Summary</h2><p>We first activate the Room Block Bridge Page exclusively for Cvent accounts confirmed as Passkey license holders via account mapping (IMS). All other accounts remain unaffected until Milestone 2.</p><p>The assumption for Milestone 1 is that a Passkey event already exists before a planner visits the bridge page.</p><p><strong>In Scope</strong></p><p>▸ Bridge page visible to any Cvent user with View or Create Event permissions on accounts with a confirmed Passkey license.</p><p>▸ Linking a Passkey room block owned by the planner's own organization from the bridge page</p><p>▸ Optional automatic enablement of Passkey RegLink and Travel Module integration at time of bridge linkage.</p><p>▸ Bi-directional syncing with the travel module</p><p>▸ Automatic sync into bridge page when a room block is linked via the Travel Module first <strong>(Note for Highlight - Travel Module workflow supports both event owned and non-owned room blocks today)</strong></p><p>▸ Real-time room block metrics and insights displayed post-linkage</p><p>▸ Deep-link navigation into Passkey Manage with MyCvent-based authentication.</p><p>▸ Support for bridge page within Event Registration, Event Essentials, and Non-Registration Shell Events.</p><p>▸ Cvent's new branding designs within Core</p><p>▸ Support Mobile responsive breaks in core</p><p>▸ <ac:link><ri:page ri:space-key="PM" ri:content-title="CDP Analytics for Bridge Pages" /></ac:link></p><p><strong>Out of Scope for First Customer Release:</strong></p><p>▸ Linking to hotel-owned or TPP-managed Passkey events from bridge page (Epic 2).</p><p>▸ Event Connection Code–based linking from bridge page (Epic 2).</p><p>▸ Planner portal user matching by email for suggested room blocks (Epic 2). </p><p>▸ Linking Cvent users out to the Planner portal from the bridge page (Epic 2). </p><p>▸ Updating the travel module user experience for Passkey linkage (Travel team scope).</p><p>▸ PLG when user has no Passkey license of their own / Linking out to Marketing Lead Gen (TBD).</p><p>▸ Creating a Passkey room block from within Core</p><p>▸ Showing the linked Core event inside Passkey's UI</p><p>▸ Linking multiple Passkey events to one Core event.</p><p>▸ The &quot;request a demo&quot; workflow.
