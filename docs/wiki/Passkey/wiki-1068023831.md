# Business Reasons and Goals

**Background:** 

The Planner Portal is a tool that is offered as part of a Passkey license, so that the stakeholders of an event can view data and manage reservations, working alongside the Event Owner during housing and room block management activities.  The Portal allows the organizer to manage controlled visibility and user permissions.  It is most valuable because it provides self-service and self-insight into real-time data about the event, and helps create a better form of collaboration between all folks managing a particular room block, event, or event organization.  

**User Personas and Jobs of the Portal:** 

**Passkey Event Stakeholders** include anyone who needs to track room block performance, drop off rooming lists, or manage reservations for an event. While the specific persona of these stakeholders can vary widely depending on the type of Passkey event, Planner Portal access is granted at 2 different levels:

-   **Event‑level planners:** Individuals designated by the event organizer with full access to an event’s inventory and metrics.
    
    -   Example: **A hotel** granting a meeting planner access for their event.
        
    -   Example: **A Passkey Event Organizer** granting their end-client access.
        
-   **Sub‑block group contacts:** Individuals who manage one or more sub‑block groups, with access limited to their group(s) inventory and metrics.
    
    -   Example: An individual sports team's travel manager who's responsible only for their team's sub-block and corresponding reservations.
        

Essentially, the Planner Portal is a subset of functionality and event visibility to what true Event Owners see.  

Currently, Passkey Planners have 2 types of dashboards - the Event Dashboard and the Planner Portal.  Almost all customers are currently on the Planner Portal, with one customer (Roche) remaining on the old Event Dashboard.

### Primary Goal(s)/Business Goals

Sunset old tech, lessen tech debt, security concerns.  The goal would be to sunset the Wildfly instance running SBD

Sunset custom code for one customer.  We have certain logic in the product that is only there because of Roche.  We need to consider how to sunset that code as part of this project. 

### Secondary Goals/Product Goals

1.  Make Roche confident and comfortable to transition to the more modern tech stack if we can close functionality gap
2.  Create a more valuable, stickier portal and increase our active users engaged in the portal 
    1.  Look at KPIs of how many planner portal users get invited to the portal today, but are not logging in
    2.  Can we measure how much time planner portal users spend within the portal? 
    3.  Specifically look at Roche adoption of Planner Portal in old version / if we keep that same level of adoption when they transition over
    4.  Renewal rates of customers overall
    5.  Measure how many people start messaging and using custom fields 
3.  Discuss and lay out which of these services need to be deprecated by end of this project plan -
