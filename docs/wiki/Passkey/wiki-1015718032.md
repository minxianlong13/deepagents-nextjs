<h2>Overview</h2><p><span>The Passkey Event Request Workflow is a serverless AWS Step Functions-based system designed to reconcile relevant details from arbitrary external input documents</span><span> </span>(<span>such as room lists, RFP-type contracts, flight manifests as well as other data sources</span>)<span> </span><span>to Passkey Events.</span><span> </span></p><p><span>The workflow processes these input documents through an</span><span> </span><strong>Event Request</strong><span> </span><span>entity,</span><span> </span><span>which follows the EMO (Event Metadata Object) document specification and is intended to represent source document information in a normalized and consumable way.  Documents are processed in source-type specific ways in order to produce EMOs in various degrees of partial completion.  Once the system has extracted, solicited and/or collected enough qualifying data to create or update a Passkey event, such steps can be automatically taken via the workflow.</span></p><p><span>The system is designed to be </span><span>idempotent,</span><span> </span><span>and AI-agent-friendly,</span><span> extensibly </span><span>supporting multiple request types and iterative data accumulation.</span></p><h2>Architecture Components</h2><h3>API Gateway Integration</h3><p><span>The system exposes a REST API v1 endpoint</span><span> </span>(<code>POST /v1/event-requests</code>)<span> </span><span>that serves as the entry point for workflow execution</span>:</p><p><strong>Endpoint</strong>:<span> </span><code>POST /v1/event-requests</code></p><p><strong>Authentication</strong>:<span> </span><span>Token-based Lambda authorizer validates bearer tokens via Cvent Auth Service</span></p><p><strong>Input Contract</strong>:</p><pre class="code-fence"><br /><code class="language-typescript"><span style="color:var(--ds-chart-gray-bold,#8590a2);">{</span><span>

data</span><span> </span>(<code>clientInputs</code>)<span> </span><span>from context-derived authentication data</span><span> </span>(<code>contextInputs</code>)<span>,</span><span> </span><span>preventing credential spoofing.</span><span> </span><span>Clients cannot override authentication fields as they Load-In (<code>step1LoadIn</code>)</h4><p><strong>Purpose</strong>:<span> </span><span>Fetch existing EventRequest from passkey-event-data service</span></p><p><strong>Input</strong>:<span> </span><code>EventRequestWorkflowInputs</code></p><p><strong>Output</strong>:<span> </span><span>Updates</span><span> </span><code>EventRequestWorkflowEvent.dbRequest</code><span> </span><span>with existing request</span><span> </span>(<span>if found</span>)<span> </span><span>or null</span></p><p><strong>Logic</strong>:<span> </span><span>Queries passkey-event-data service using</span><span> </span><code>requestType</code><span> </span><span>and type-specific identifiers</span><span> </span>(<span>e.g.,</span><span> </span><code>fileId</code><span> </span><span>for ROOM_LIST</span>)</p><h4>Step 2: Upsert Request (<code>step2UpsertRequestFromInput</code>)</h4><p><strong>Purpose</strong>:<span> </span><span>Create or update EventRequest in database</span></p><p><strong>Input</strong>:<span> </span><span>Current workflow state with</span><span> </span><code>dbRequest</code><span> </span><span>from Step 1</span></p><p><strong>Output</strong>:<span> </span><span>Updated</span><span> </span><code>EventRequestWorkflowEvent.dbRequest</code><span> </span><span>with persisted request</span></p><p><strong>Logic</strong>:</p><ul><li data-uuid="8b65e007-3b94-4691-a6eb-dcca902772dd">If<span> </span><code>dbRequest</code><span> </span>exists: Performs PATCH update with new data from<span> </span><code>clientInputs</code></li><li data-uuid="7b95379c-ad5f-4b4c-b10b-d4052570a33c">If<span> </span><code>dbRequest</code><span> </span>is null: Creates new EventRequest</li><li data-uuid="f25cecb2-9754-44a6-bce8-8d3fad876765">Persists changes via passkey-event-data service</li><li data-uuid="39b76350-59f1-4c73-a218-9659c68ebcec">Supports partial updates for iterative data accumulation</li></ul><p><strong>AI-Agent Friendly</strong>:<span> </span><span>Allows multiple invocations to progressively build up EventRequest data</span></p><h4>Step 3: Verify Request (<code>step3VerifyRequest</code>)</h4><p><strong>Purpose</strong>:<span> </span><span>Validate EventRequest completeness and determine next action</span></p><p><strong>Input</strong>:<span> </span><span>Current workflow state with updated</span><span> </span><code>dbRequest</code></p><p><strong>Output</strong>:<span> </span><span>Decision to proceed or terminate</span></p><p><strong>Logic</strong>:</p><ul><li data-uuid="77489785-4814-41ee-b65d-eac286a8fd00">If<span> </span><code>assemblyOnly === true</code>: Terminate (data collection mode)</li><li data-uuid="561e540a-220d-4452-a4b5-0b5893690063">If insufficient data for event creation: Terminate with validation errors</li><li data-uuid="996f8ea5-e809-42db-be7d-e33b1fa25b40">If validation passes: Proceed to Step 4</li></ul><p><strong>Idempotency</strong>:<span> </span><span>Enables</span><span> </span>&quot;<span>assembly mode</span>&quot;<span> </span><span>where requests can be built incrementally without triggering event creation</span></p><h4>Step 4: Create Event (<code>step4CreateEvent</code>)</h4><p><strong>Purpose</strong>:<span> </span><span>Construct Passkey event from EventRequest</span></p><p><strong>Input</strong>:<span> </span><span>Validated</span><span> </span><code>EventRequestWorkflowEvent.dbRequest</code></p><p><strong>Output</strong>:<span> </span><span>Event ID from passkey-reglink service</span></p><p><strong>Logic</strong>:</p><ul><li data-uuid="2c834e56-f8a8-49f5-8a25-e6e25ec800e6">Checks EventRequest.eventId to ensure event hasn't already been created.</li><li data-uuid="32fa4efa-6e6e-4926-8b83-78e67547699b"><s>Transforms <code>EventRequest.eventMetadataObject</code> into passkey-reglink API format</s> passkey-reglink API is already EMO-friendly.</li><li data-uuid="fa70bac5-350b-41aa-89e7-be0f72838078">Invokes passkey-reglink HTTP API to create event</li><li data-uuid="95e237b0-26b8-4ebd-80c0-70220158682a">Stores returned<span> </span><code>eventId</code><span> </span>in workflow state</li></ul><h4>Step 5: Patch Request Status (<code>step5PatchRequestStatus</code>)</h4><p><strong>Purpose</strong>:<span> </span><span>Update EventRequest with creation results</span></p><p><strong>Input</strong>:<span> </span><span>Workflow state with</span><span> </span><code>eventId</code><span> </span><span>from Step 4</span></p><p><strong>Output</strong>:<span> </span><span>Updated</span><span> </span><code>dbRequest</code><span> </span><span>with service</span></p><h4>Step 6: Post-Creation Callback (Choice Step)</h4><p><strong>Purpose</strong>:<span> </span><span>Execute request-type-specific type-specific callback</span>:</p><ul><li data-uuid="a94acccf-cc7d-4baa-b2d8-d39f246d25aa"><code>ROOM_LIST</code><span> </span>→<span> </span><code>step6aRoomlistCallback</code></li><li data-uuid="7223bdbf-ee65-4f2a-b633-c2d02532b5ce"><code>GML</code><span> </span>→<span> </span><code>step6bGMLCallback</code></li></ul><p><strong>Extensibility</strong>:<span> </span><span>New request types add new choice branches</span></p><h2>Compensatory Flow</h2><p><span>The workflow implements a cascading rollback pattern with 2 retry attempts per step before triggering compensation</span>:</p><h3>Main Flow Compensation (Steps 1-5)</h3><p><strong>Default Retry Policy</strong>:<span> </span><span>Each step retries up to 2 times with exponential backoff</span><span> </span>(<span>rate</span>:<span> </span><span>2</span>)</p><p><strong>Compensation Chains</strong>:</p><ul><li data-uuid="0375e690-f9ce-46ec-8705-cfd5ad94e89b"><strong>Step 1 fails</strong>: →<span> </span><code>MainFlowFailed</code><span> </span>(no compensation needed)</li><li data-uuid="504731bb-e5aa-42f4-80b5-adcad8e7caa9"><strong>Step 2 fails</strong>: →<span> </span><code>compensateStep1LoadIn</code><span> </span>→<span> </span><code>MainFlowFailed</code></li><li data-uuid="45c7814e-1372-4986-b6b7-078863679bf1"><strong>Step 3 fails</strong>: →<span> </span><code>compensateStep2UpsertRequestFromInput</code><span> </span>→<span> </span><code>compensateStep1LoadIn</code><span> </span>→<span> </span><code>MainFlowFailed</code></li><li data-uuid="43377a09-8e37-4870-927b-2a69ffea2f40"><strong>Step 4 fails</strong>: →<span> </span><code>compensateStep3VerifyRequest</code><span> </span>→<span> </span><code>compensateStep2...</code><span> </span>→<span> </span><code>compensateStep1...</code><span> </span>→<span> </span><code>MainFlowFailed</code></li><li data-uuid="9f0c5dad-4a2f-404c-825c-57a727ce93cc"><strong>Step 5 fails</strong>: →<span> </span><code>compensateStep4CreateEvent</code><span> </span>→<span> </span><code>compensateStep3...</code><span> </span>→<span> </span><code>compensateStep2...</code><span> </span>→<span> </span><code>compensateStep1...</code><span> </span>→<span> </span><code>MainFlowFailed</code></li></ul><p><strong>Compensation Responsibilities</strong>:</p><p>Note: State may require separate dbRequestNew and dbRequestOrig attributes in order to support rollback.</p><ul><li data-uuid="a6c40678-a5dd-4800-8f9d-c7100c57f089"><code>compensateStep1LoadIn</code>: Clear any cached request data from workflow state</li><li data-uuid="9e33b242-59ba-4982-9589-8af0d4f81aff"><code>compensateStep2UpsertRequestFromInput</code>: Delete or revert EventRequest in database</li><li data-uuid="c21519b1-aa3e-4296-a8ea-37a4d4593d17"><code>compensateStep3VerifyRequest</code>: Clear validation state/flags</li><li data-uuid="426b7706-cd09-490e-89fc-a647fe42b893"><code>compensateStep4CreateEvent</code>: Possibility: Delete created event via passkey-reglink API</li><li data-uuid="2ff95949-4d94-4a8b-92d5-ca2ad7004985"><code>compensateStep5PatchRequestStatus</code>: Revert EventRequest status to previous state</li></ul><h3>Post-Success Compensation (Steps 6a/6b)</h3><p><strong>Isolation</strong>:<span> </span><span>Steps 6a and 6b failures do NOT trigger main flow rollback</span></p><p><strong>Compensation</strong>:</p><ul><li data-uuid="47f48c7c-a02f-4b05-b4a2-4f019abd2173"><strong>Step 6a fails</strong>: →<span> </span><code>compensateStep6aRoomlistCallback</code><span> </span>→<span> </span><code>PostSuccessCallbackFailed</code></li><li data-uuid="21929c8c-2810-4c72-a042-3500077c0cd4"><strong>Step 6b fails</strong>: →<span> </span><code>compensateStep6bGMLCallback</code><span> </span>→<span> </span><code>PostSuccessCallbackFailed</code></li></ul><p><strong>Rationale</strong>:<span> </span><span>Event creation succeeded;</span><span> </span><span>callback failures should not undo the event.</span><span> </span><span>Compensatory steps handle cleanup of callback-specific side effects only.</span></p><h2>Data Extensibility</h3><ul><li data-uuid="d65c3606-e7c3-4e19-a387-782ec54fbfcb">Request types are enum-based and easily extended</li><li data-uuid="d5924036-c22b-48b7-9d37-0204b6a29ddb">Client input contracts use TypeScript interfaces with inheritance</li><li data-uuid="ee4da3fc-9c80-494e-aea2-bd131aaabec5">Workflow choice step dynamically routes based on<span> </span><code>requestType</code></li><li data-uuid="aa08fc50-c621-4120-97c6-220cec273319">VTL template passes through all<span> </span><code>clientInputs</code><span> </span>fields without modification</li></ul><h3>2. Idempotency</h3><ul><li data-uuid="ba3480a3-caad-4cea-98e3-eb8923cc89e7">Multiple workflow invocations with same<span> </span><code>fileId</code><span> </span>update existing EventRequest</li><li data-uuid="f3a90f1b-d048-4c7b-b63a-9d383a2ac58c"><code>assemblyOnly</code><span> </span>flag enables data accumulation without side effects</li><li data-uuid="8d72257d-39ff-41ef-88e6-b9108520a8d8">Step 3 verification prevents duplicate event creation</li></ul><h3>3. AI-Agent Friendly</h3><ul><li data-uuid="f804d456-5a33-43f6-bcd6-be15e44dbf6c">Supports iterative data collection across multiple API calls</li><li data-uuid="539ec67e-0aa5-40dd-b423-1b0fc765f8cd">Partial updates allow progressive refinement of EventRequest</li><li data-uuid="38510c75-1429-46d7-b522-de3b2fb5ae8a">Validation step provides clear feedback on missing data</li><li data-uuid="89fa8fd0-46e7-4900-8355-2276ee229d52">Stateful EventRequest entity maintains context between invocations</li></ul><h3>4. Security</h3><ul><li data-uuid="e5b516c2-7769-45ac-9a7c-629ca2757a6b">All input is JSON (data-only: no markup, no injections, no arbitrary scripts)</li><li data-uuid="cd27721d-4bfb-4474-9291-c5775ec508ec">Authentication data isolated in<span> </span><code>contextInputs</code><span> </span>(non-spoofable)</li><li data-uuid="177ee670-ad7e-40a8-827d-55eaeaa5afc8">Client data isolated in<span> </span><code>clientInputs</code><span> </span>(untrusted)</li><li data-uuid="2bbb6648-6580-4c16-9571-e9c269a0acf2">API Gateway authorizer validates all requests via cvent-auth</li><li data-uuid="1d594932-4450-465f-97cf-7b909532eced">VTL template enforces separation of concerns</li></ul><h3>5. Reliability</h3><ul><li data-uuid="3a978ed4-5cda-4fbd-8984-06e4886cf14c">Automatic retries (2 attempts per step)</li><li data-uuid="cc997acd-a73c-44e2-ad11-e8c995cfcb8a">Compensatory rollback for transactional consistency</li><li data-uuid="3cb8b9d8-40a6-4c15-8a37-3a427f30e3a9">Post-success callbacks isolated from main transaction</li><li data-uuid="1ea37151-5ccd-44e2-9b14-f29625dfd6a1">CloudWatch (and Datadog) logging at each step</li></ul><h2>Future Enhancements</h2><ol><li data-uuid="dce3781f-703f-4a8c-95ea-44b344e8cdfb"><strong>Update Existing Events</strong>: Extend workflow to support updating events (not just creation)</li><li data-uuid="191c4f4d-5b04-444f-a011-b85a8d033e2d"><strong>Additional Request Types</strong>: Add support for new document types beyond ROOM_LIST and GML</li><li data-uuid="3a0c69fc-ca44-43f4-9c69-ff8862e21318"><strong>Async Callbacks</strong>: Convert Step 6 callbacks to asynchronous processing for long-running operations</li><li data-uuid="39717290-8115-4c99-b5e7-4aef9d0f93b9"><strong>Validation Rules Engine</strong>: Externalize Step 3 validation logic for dynamic rule configuration</li><li data-uuid="7015baeb-6924-40da-b898-8668cb791c3a"><strong>Event Versioning</strong>: Track EventRequest versions for audit and rollback capabilities</li></ol>
