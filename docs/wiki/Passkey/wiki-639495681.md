## Overview

Hotels in CW events are not getting notified that they are added to events.

## Background Reading

None.

## Problem

Organizers can use the Hotel Welcome Emails to communicate with their hotels, but the problem is that these may not be turned ON or configured properly to be sent to the hotels.

In this case, hotels don't receive any notifications that they are part of the event.

## Solution Outline

**Short term - use existing functionality -  Cvent JIRAd1d78885-1a8e-3259-b68d-3df198ee3d46GROUP-99079**

-   Update templates for
    -   Done - Hotel Integrated
    -   Done - Hotel Non-Integrated
    -   NOT YET PLANNED - Hotel Reservation Notification emails
-   NOT YET PLANNED - Consider turning ON the emails when added into events (currently they are always OFF)

**Next step - build out new feature**

-   Introduce a new System-level email notifications for hotels which is NOT controlled nor customizable by the event organizer. This is where we would control instructions for Integrated and non-integrated hotels and even support the ability to scale out more based on brand/chain or integration types. Maybe we use the SMART Alert framework for this? Maybe something else?
-   This will impact various areas of Passkey

This was accomplished via Cvent JIRAd1d78885-1a8e-3259-b68d-3df198ee3d46GROUP-99079 and its stories by updating our global template for the Hotel Welcome Email (integrated and non-integrated).

## Long Term Solution (Convert Campaign to System Email)

If we make the Hotel emails into system generated emails this implies:

-   Hide the existing Hotel Welcome (Integrated), Hotel Welcome (Non-Integrated), and Reservation Notification from organization profile, bundles, and events
-   Rename "Hotel Notify" to something else TBD, as a **single email** which allows planners to create and customize their own hotel email that they can send on a schedule of their choosing

### Org Libraries

Existing orgs:

-   We'll need to hide the 3 campaigns in all the Org libraries. 
-   We probably would want to keep just the name and link for a Preview that works.
-   This would allow customers to still have access to their predefined content, in case they want to reference it or copy/paste somewhere else.
-   This will leave essentially just "Hotel Notify" (to be renamed TBD) as the only campaign they can configure and sent to Hotels.
-   NOTE - we could potentially hide the 3 campaigns after X weeks/months have elapsed?

New orgs created after release:

-   Will ONLY have 1 campaign like "Hotel Notify" visible in this area

### Bundles

In existing bundles:

-   Hide the 3 rows below, and ensure that they are ignored when creating events

In new bundles created after release:

-   Don't include these 3 rows

  

We'll just leave the "Hotel Notify" as the only selectable campaign here.

Since Orgs don't edit anything here, it's fine to hide these campaigns that we/they won't use anymore.

  

### Events

Existing events:

-   We'll need to hide the existing Hotel Welcome Emails (both) and Hotel Reservation Notification from existing events.
-   If no campaigns were added, I suggest hiding the 3 rows completely. 
-   If a campaign was already added, we should show the row, but turn the campaign OFF with a tooltip explaining this and only have the name and Preview
    -   **Why? - To allow the user to recover any useful information (via Preview) that they might have input in this event.**
    -   **This could be temporary (e.g. for X weeks or X months) or we could just let these existing events "phase out" as time goes on.**
-   This will leave only "Hotel Notify" as the single campaign

  

New events created after release:

-   We'll need to hide the existing Hotel Welcome Emails (both) and Hotel Reservation Notification from these events
-   This will leave only "Hotel Notify" as the single campaign

  

NOTE - if we hide these existing campaigns _immediately_, for all events, it could be confusing.  Also, customers will not be able to view/access any custom content they might have input.

This could be frustrating.   And they won't easily know if the campaign has fired or not.   

I think there could be pushback in other words.

Again, it could be a temporary phase where we keep them visible, and THEN we remove them from view entirely.

### New SmartAlert for "Hotel Added"

This section proposes a concrete way of replacing the Campaigns that are hidden, using our SmartAlerts.

1.  Whenever a new Citywide event (owned by a plain org) or Multi-Property event (owned by a sister property organizer) is created, we will automatically insert a new type of alert into the event.
    1.  It will have a pre-set name, content, settings, and will be turned ON within the event.
2.  The alert is fired when...
    1.  Maybe need a concept of a "launch date" in the future that the system could key off of to send the alert. This would be after the general open but before the event start.
    2.  We may also need a concept of a "ready" status the organizer can switch on the hotel in the CW event?
    3.  NOTE - must consider the "hide from hotel"  (need to find more details on this feature and explain)

  

Note - Look at the "confirm inventory" feature and if we can expand that.

  

This approach may be preferable, as it's transparent to the user, it allows them some control over recipients, and also for the ability to add their own custom message to the default content (which Passkey will control).

Beyond that, it can be translated to different locales by Passkey and sent using the correct locale.
