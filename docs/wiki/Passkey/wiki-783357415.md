# Introduction

This document is intended to track progress towards fixing intermittent issues with session hydration in Resdesk and RDK2.  At the time of creating this document (Dec 2024), this issue is being reported by customers and is observed in data dog logs, but it is not yet well understood.

The different sections in this document are to assist in the analysis of data, diagnosis of the problem (or problems) and finally, formulating a problem resolution.

# What We Know

## General Observations

-   Customers have reported having their Resdesk sessions abruptly aborted while navigating both RDK2 and Resdesk.
-   Customers are being forwarded to a 404 error screen.
-   In regards to RDK2, any GQL query error results in a forward to the 404 error screen.  This is not good, but I have a theory:
    -   User browses to page in RDK2 (which in turn causes the side nav to be displayed)
    -   We already know we have query issues in the side nav right now.  Side nav is likely producing an error.
    -   Immediately, i have a feeling that we can cut down on the customer impact of these errors by not blowing up the UI when an error is encountered.  Blast radius of the error should be limited to affected components _only_.
-   In regards to Resdesk Classic, these activities and associated errors are easily observable in Datadog. Over regular business hours, DD reports upwards of 1500-2000 visits to the 404 page per hour.
