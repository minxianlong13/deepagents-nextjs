## **Introduction**

This document provides a comprehensive guide on integrating LaunchDarkly with Passkey-RDK2.

### **What is LaunchDarkly?**

LaunchDarkly is a feature management platform that allows development teams to control the release of features through feature flags.

#### LaunchDarkly Onboarding Wiki: [https://wiki.cvent.com/display/RD/LaunchDarkly+Onboarding](https://wiki.cvent.com/display/RD/LaunchDarkly+Onboarding) (Provided by the LaunchDarkly Tech Team)

**Slack Channel:** #tech-launchdarkly

### Verify Access

Access can be verified through Okta. Reach out to \`#is-help\` if you do not have access to LaunchDarkly.

### Launch Darkly Client Authentication Methods

There are three authentication methods:

-   **SDK Keys:** Good for server-side and AI SDKs (should be kept secret).
-   **Mobile Keys:** Used for some client-side SDKs (no need to keep secret).
-   **Client-Side IDs:** For JS-based client-side SDKs. They need to be kept secret and cannot be reset.

  

> **Note:** Cvent’s licensing model prefers using server-side SDK keys.

SDK keys are different per project per environment. You will need the corresponding key to evaluate the flags in the corresponding project and environment.

### Creating a Flag

1.  **Flag Naming**: Recommended practice is to name a flag as an instructional sentence that begins with an action and concludes with a subject (human-readable).
    1.  "Rollout: a new feature"
    2.  "Configure: a setting"
    3.   "Allow: an action"
    4.  "Enable: an entitlement"
    5.  "Show: an offer"
2.  **Flag Key Conventions:** Once created, cannot be modified (flag name can be updated whenever we want) (code-readable).
    1.  We will use the flag key in our code.
    2.  A suggested key is auto-populated for help when we create a flag.
    3.  LaunchDarkly supports a number of naming conventions: camelCase, PascalCase, snake\_case, kebab-case.
    4.  Projects are set to use kebab-case.
3.  **Tags:** Used for access control (use your team’s tag).
4.  **Flag Links:** Can be used to link to external systems, e.g., JIRA ticket.
5.  **Flag Categories:** When creating a feature flag, you can choose whether it is temporary or permanent.
6.  **Flag Configuration:** Select how the flag will be used.

> Note: Flag keys once created, cannot be modified.

#### Temporary Flag Use Cases

-   Release: Safely release new functionality or code changes to production.
-   Experimental: Test hypotheses and continuously optimize through beta users and A/B/n tests.

#### Permanent Flag Use Cases

-   Entitlement: Manage different levels of functionality provided to various types of customers.
-   Operational: Use for kill switches, circuit breakers, log levels, and other utility flags, such as rate limiting.

  

### Locate SDK Keys

#### First Method

1.  Go to the list of flags.
2.  Click on the three dots next to the environment for which you need the key.
3.  Copy the SDK key.

  

  

#### Second Method

1.  Go to settings (Gear icon on bottom left)
2.  Go to Projects.
3.  Search for your project (Passkey).
4.  Select Environments.
5.  Click on the three dots next to the environment you need the key for.
6.  Copy the SDK key.

  

Alternatively, you can try visiting the [https://app.launchdarkly.com/projects/passkey/settings/environments?env=development&env=staging&selected-env=staging](https://app.launchdarkly.com/projects/passkey/settings/environments?env=development&env=staging&selected-env=staging) .

### Targeting

Targeting in LaunchDarkly refers to the ability to control the visibility of features for specific users or groups based on predefined rules and conditions. This allows you to enable or disable features for particular segments of your user base, providing a high level of customization and control over feature rollouts.

###  Default Values

Default values in LaunchDarkly refer to the fallback values that are used when a feature flag is not explicitly set for a user or when the LaunchDarkly client cannot connect to the service. These values ensure that your application behaves predictably even if the feature flag configuration is unavailable.

  

We make sure we add a default value for the flag to \`LaunchDarklyDefaultValues\` (\[[https://stash.cvent.net/projects/PC/repos/passkey-rdk2/browse/packages/app/src/components/eventOverview/constant.ts#4](https://stash.cvent.net/projects/PC/repos/passkey-rdk2/browse/packages/app/src/components/eventOverview/constant.ts#4)\](#)).
