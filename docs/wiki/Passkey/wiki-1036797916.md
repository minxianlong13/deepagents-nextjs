Technical Analysis

  

## Objective:

Deliver an event-level quick view dashboard accessible directly from the event listing/home page, allowing qualified users to see night‑by‑night block and pickup at a glance for a selected event and hotel, without drilling into the full event → hotel flow.

This reintroduces and modernizes the “night‑by‑night preview on the home screen to quickly see block and pickup” that existed in the classic experience and was removed in the new home page design.

## Problem Statement:

-   Users must click into an event, then into the hotel inventory pages to see nightly block and pickup.
    
-   Scanning multiple events and hotels is slow and repetitive; there is no way to quickly “flip” through hotels and compare high‑level inventory health from the home/search screen.
    
-   Customers (e.g., **MGM** and **ConferenceDirect**) have explicitly asked for the home‑page nightly preview back, to quickly triage multiple events at once and get a fast pulse on block utilization and pickup without deep navigation.
    

This slows down:

-   Daily revenue and pickup checks
    
-   Early identification of risk nights (over/under performance)
    
-   Conversations with hotels and stakeholders who expect quick, concrete numbers
    

## Vision:

From the event listing/home page, a qualified user can open a Quick View Dashboard for any event, select a hotel and (optionally) room/attendee filters, and see a compact nightly calendar/grid of:

-   Contracted block
    
-   Pickup
    
-   Remaining inventory
    
-   Key dates and configuration flags (cutoff, reservation access, GroupLink status, etc.)
    

They can **flip through hotels** in seconds, without leaving the home page, mirroring the speed and convenience of the old classic “expand row” quick view while aligning with the new UX.

**In scope:**

-   Event‑level Quick View entry from event listing/home page
    
-   Single‑hotel quick view per event (with fast switcher to move between hotels)
    
-   Basic room/attendee selection/filtering
    
-   Night‑by‑night inventory view (block vs pickup vs remaining)
    
-   Permission‑aware visibility of the Quick View CTA and data
    

**Out of scope:**

-   Upsell tile

## Users Personas

-   **Event Organizer / Org User**
    
    -   Owns or manages multiple events; monitors block and pickup across hotels.
        
    -   Needs quick signal when events or specific nights are under/over‑performing.
        
-   **Hotel / Passkey User**
    
    -   Focused on inventory performance at hotel level.
        
    -   Needs a simple way to confirm block utilization and pacing for events hosted at their property.
        

## Features:

**User flow**

1.  User lands on the Event Listing/Home page.
    
2.  Quick View initializes with:
    
    -   Section 1: Header (event identity)
        
    -   Section 2: Event tile (status & key dates)
        
    -   Section 3: Event selection (hotel/room/attendee/date filters)
        
    -   Section 4: Inventory (night‑by‑night grid)
        

**User Permissions** 

-   A user must already have access to the event in the event listing page to see the Quick View CTA and to open Quick View for that event.
    

-   Only users who have access to the primary hotel inventory screen (i.e., can see hotel‑level inventory and pickup in the current experience) should see the Quick View CTA and underlying inventory metrics for that event.
    
-   Users without this permission:
    
    -   Do not see the Quick View CTA at all OR
        
    -   See a disabled CTA with tooltip: “You don’t have access to hotel inventory for this event” (final behavior to be decided during UX review).
        

**Header**  
The Quick View Dashboard must display a compact header at the top that clearly identifies the event the user is viewing.

Fields

-   Event name
    
    -   Full display name of the event, as configured in the event setup.
    -   Used as the primary identifier in the header.
-   Event address
    
    -   The main physical location of the event (e.g., venue address, city, state, country).

**Event Tile**

Below the header, show a compact event tile that summarizes the event’s status and key configuration details relevant for understanding inventory and pickup at a glance.

Fields:

-   Event status (Open / Closed)
    
    -   Definition: Indicates whether the event is currently accepting reservations or is in an active state.
    -   Display behavior:
        -   If the event is Open, show a green status tag labeled “Open”.
        -   If the event is Closed, show a red status tag labeled “Closed”.
-   Inventory start date
    
    -   Definition: The calendar date from which room inventory (contracted blocks) begins for this event/hotel configuration.
    -   This is typically the first night for which contracted inventory exists in the system.
    -   This includes the shoulder nights for the event.
-   Reservation open date
    
    -   Definition: The date when reservations are first made available to attendees for booking (i.e., when the booking window opens).
    -   After this date, guests can start creating reservations via the configured booking channels.
-   Reservation close date
    
    -   Definition: The date when reservations are no longer accepted through the standard reservations flow (i.e., when the booking window closes).
-   Event ID
    
    -   Definition: The unique identifier of the event in the system (e.g., event code or stub used across admin tools and reporting).
-   Currency (default currency for the event)
    
    -   Definition: The primary currency configured for the event, used for pricing and revenue metrics (e.g., USD, EUR).

  

**Event Selection**

Provide a selection panel that lets users narrow down which hotel, room, and attendee segment they are viewing, and clearly display key booking window and integration status information.

#### Hotel Selection

-   **Hotels for the selected event (single‑select)**  
    -   **Definition:** The list of all hotels associated with the selected event that the user is permitted to view.
    -   The user can select **exactly one hotel** at a time.
    -   Changing the hotel updates all dependent information (rooms, attendee filter, dates, inventory grid).
    -   If no hotels are defined then a placeholder will be visible asking users to add hotels for the event.

#### Room Selection

-   **Rooms for the selected hotel (all or single)**  
    -   **Definition:** The set of room types configured for the selected hotel under the event’s block.
    -   Selection options:
        -   **“All rooms” (default)** – aggregates block and pickup across all room types.
        -   A **single room type** – filters block and pickup metrics to that specific room type only.
    -   Changing this selector recalculates the Inventory section accordingly.

#### Attendee Selection

-   **Attendee for the selected room (all or single)**  
    -   **Definition:** The attendee types or segments associated with the selected room/hotel combination (if attendee segmentation is configured).
    -   Selection options:
        -   **“All attendees” (default)** – aggregates across all attendee types.
        -   A **single attendee type** – filters to that segment only (e.g., VIP, staff, standard attendee).
    -   If attendee types are not used for the event, this control may be hidden.

#### Reservation Access Date

-   **Reservation access date**  
    -   **Definition:** The effective date from which the selected hotel/room/attendee combination is accessible for reservations.
    -   This may be identical to the Reservation open date in Section 2 for simple configurations, but could differ by room or attendee type in more complex setups.
    -   Helps users understand **from when** bookings are/ were allowed for the currently selected slice.

#### Cutoff Date

-   **Cutoff date**  
    -   **Definition:** The date when the contracted block for the selected configuration stops being protected (i.e., when unsold inventory can be released or when attendees can no longer book into the block).
    -   After this date, behavior typically changes (e.g., rooms convert to free sell or become unavailable).
    -   This date often aligns with, but is not always identical to, the Reservation close date.

#### GroupLink Setup Status (for Integrated Hotels)

-   **GroupLink setup status (integrated hotels only)**  
    -   **Definition:** Indicates whether **GroupLink integration** has been configured and is active for the selected hotel.
    -   **Display behavior (clarified):**
        -   If GroupLink is **not set up / inactive**, show a **red indicator** (e.g., “GroupLink not configured”).
        -   If GroupLink **is set up / active**, show a **green indicator** (e.g., “GroupLink active”).
    -   This status is only shown for hotels where GroupLink integration is relevant; for non‑integrated hotels the field may be hidden or show a neutral “Not applicable” state.

### Inventory

**Requirement (Inventory Grid – Block & Pickup)**  
Provide a **night‑by‑night inventory view** for the currently selected event, hotel, room, and attendee configuration that surfaces the key block and pickup metrics at a glance.

**Core Concept**

-   **Inventory details in pickup**  
    -   **Definition:** For each date in the relevant range, show how the contracted room block is being consumed. At minimum, the grid should represent:
        -   **Contracted block** – number of rooms allocated for that night.
        -   **Pickup** – number of rooms actually booked/consumed against the block for that night.
        -   **Remaining inventory** – derived value (`Block – Pickup`) representing rooms still available in the block (non‑negative).
