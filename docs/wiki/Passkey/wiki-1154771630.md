This page captures the current Room List and Contract workflow design as it exists today.

It is intended to help compare both workflows and reuse the same design and backend patterns where appropriate.

This is not a formal reference guide or final design document. The Contract workflow is still under active development, so this may change over time.

# Overview

This page documents the current **RoomList Create Event flow** and the proposed **Contract Create Event flow**.

The RoomList flow is based on:

```text
Spreadsheet upload
Header / date mapping
Room type mapping
Inventory summary generation
Summary review
Event creation workflow
RoomList handoff
```

The Contract flow should follow the same page structure, but instead of spreadsheet header parsing, it should use PDF extraction through Textract and allow the user to review/correct extracted fields before creating the event request.

The key design goal is to keep the Contract flow aligned with the existing RoomList architecture while replacing spreadsheet-specific mapping with PDF extraction and user-reviewed contract field mapping.

# 2\. Corrected Contract Flow

## 2.1 Contract Flow Overview

The Contract flow should mirror the RoomList page structure, but instead of spreadsheet header parsing, it should use PDF/Textract extraction.

The high-level Contract flow should be:

```text
Upload PDF
  -> Parse with Textract
  -> Produce generic extracted data / future EMO
  -> Show extracted fields in UI
  -> User reviews/corrects fields
  -> Build Contract Event Request / EMO
  -> Save Contract Event Request
  -> Summary review
  -> Create event workflow
```

# 5\. Key Design Decision

The Contract parser/review flow should happen before saving or finalizing the Contract Event Request.

It should not happen only in Step 6 handoff.

## 5.1 Correct Contract Flow

B\["Extract Data with Textract"\] B --> C\["Review or Correct Extracted Fields"\] C --> D\["Build Contract EMO"\] D --> E\["Save Contract Event Request"\] E --> F\["Summary Review"\] F --> G\["Create Event Workflow"\]\]\]>

  

## 5.2 Incorrect Contract Flow

B\["Save Contract Event Request Early"\] B --> C\["Create Event Workflow"\] C --> D\["Extract or Handoff in Step 6 Only"\]\]\]>

The incorrect flow delays extraction/review too late and does not give the user a proper chance to correct extracted data before the event request is created.

## EMO Fields Missing for Full Contract Support

The following fields are not currently supported by the EMO if we want to preserve Contract-specific data:

```ts
hotelName
hotelAddress
cutoffDate
```

However, for the MVP, these fields do not need to be added to the EMO.

Since this is an HD use case and the user selects the hotel before uploading the file, the hotel is already known. The EMO can continue identifying the hotel by:

```ts
hotels[].id
hotels[].hotelCode
hotels[].glCode
```

Therefore:

```text
hotelName and hotelAddress can stay in the parser review output only.
They do not need to be persisted into the EMO for MVP.
```

The same applies to `cutoffDate` unless Product confirms it is mandatory for the first iteration.

# 9\. Final Recommendation

The Contract flow should reuse the same mental model as RoomList:

```text
Upload
  -> Extract / Map
  -> Review
  -> Generate Summary
  -> Save Event Request
  -> Create Event
```

The main difference is the source of structured data:

```text
RoomList: Spreadsheet columns and room type mappings
Contract: PDF/Textract extracted fields and user-reviewed overrides
```

This keeps the product experience consistent and reduces risk by following the existing RoomList architecture.

The most important correction is:

```text
For Contract, extraction and user review must happen before the Contract Event Request is finalized and before the create event workflow is triggered.
```
