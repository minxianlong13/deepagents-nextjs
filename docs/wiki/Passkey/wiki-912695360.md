This document provides a step-by-step guide for creating a **feature flag** in **LaunchDarkly** within the context of the **Passkey project**. It includes an example currently used in the **Resdesk application**.

> **Note:** The current implementation has certain client-side limitations. A follow-up ticket will address these constraints to improve usability and flexibility. Please reach out to me directly if you require any clarification or assistance while reviewing or implementing this configuration.

### Accessing LaunchDarkly

1.  Navigate to [https://cvent.okta.com](https://cvent.okta.com).
    
2.  Search for **LaunchDarkly** in the Okta dashboard and open the application.
    
3.  In LaunchDarkly, ensure the **Passkey** project is selected using the dropdown menu in the top-left corner.
    

  

* * *

###   
Creating a New Flag

A **flag** in LaunchDarkly serves the same purpose as an **experiment** in Backstage.

To create a new flag:

1.  Click **Create → Flag**
    
2.  Provide the following:
    
    -   **Name**: A human-readable name for the flag
        
    -   **Key**: A unique identifier used in code (e.g., in taglibs or Java classes)
        
    -   **Mentainer :** 
        -   designate the appropriate team(s) responsible for maintaining the flag.
            
              
            
            Multiple teams can be listed as owners if needed.
            
              
            
        -   Only the added Team are able to enable/disable or update the variables/Flags 
            

  

###   
Example: Resdesk Flag

A current example implemented in **Resdesk**:

-   **Name**: `Enable Resdesk Beta UI`
    
-   **Key**: `enable-resdesk-beta-ui`
    
-   **Owner**: sprint-metre-stick

### Configuring the Flag

#### Choose the Flag Type:

-   **Boolean** – For simple ON/OFF control
    
-   **JSON** – For passing metadata or structured configuration
    

> ⚠️ Once a flag is created, its configuration type **cannot** be modified.

  

#### For JSON Flags:

Include the following to enable the feature:

json

  

This structure is required for the flag to function correctly in services.

### Defining Flag Rules

After creation, specify how the flag behaves per environment.

#### Global Toggle (Environment-Specific):

-   Navigate to the desired environment tab.
    
-   Set the flag status to either **ON** or **OFF**.
    

  

#### Deploy to different Environment:

You could select the + next to development to add any environments   
  

#### Conditional Targeting Based on Participant ID:

  

importantthis is important , you have to select same details to be able to load participntID form Resdesk . 

  

1.  Click **Add Rule**
    
2.  Configure the following:
    
    -   **Context kind**: `event`
        
    -   **Attribute**: `[participant.id](http://participant.id)`
        
    -   **Operator**: `is one of`
        
    -   **Values**: List the allowed participant IDs
        
3.  Set the **default rule** to **OFF** for all other users.
