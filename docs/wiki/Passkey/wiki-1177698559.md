## Goals

-   ## **Event Registration Path with Travel Module**
    
    * * *
    
    We have currently settled on a strategy where we have a bi-directional solution to solve for Events that also use the Travel module.  
    
    1.  Leave the Hotel and Travel Booking Tool as is, we don't want to remove the workflow for just the one Passkey option out of configuring your travel setup - Not everyone is going to use the room block page. 
    2.  We also believe there are use cases where event owners only want to see room block pickup and not configure that room block to be part of their event registration workflow / maybe they don't have registration for their event. We will continue to explore why users won't or don't want to use Registration during discovery 
    
    For requirements in this use case: 
    
    1.  Provide an easy experience to navigate back and forth from the two pages (Travel to Room Blocks / Room Blocks to Travel) 
    2.  Provide a shortcut to the Passkey Attendee Type mapping configuration in the Travel Module setup.  We need to make it easy for the user to understand from the Room Block page when they have additional CTAs to take under the Travel module that are not complete (Ex: Attendee mapping) 
    3.  Provide a workflow for if User wants to link the room block, but doesn't want to enable Travel / link to registration 
    4.  If Passkey room block is linked from Travel page first, surface high-level Room Block performance metrics and key dates on the room block.  User should not have to link again from the Room block page.
