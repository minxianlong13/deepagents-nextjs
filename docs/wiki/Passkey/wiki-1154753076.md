## Background

This next requirement is to focus on supporting a workflow where a Cvent Event Customer wants to link to a Passkey room block which they do not own.  

Many times, a Passkey room block is managed and owned either by the hotel directly **or** by a TPP or housing organization, which may not run every aspect of that event planning process (like registration, onsite planning, sourcing, etc that could be owned by the primary organization in-house)

In this scenario, the Cvent Event Management Customer: 

1.  The user in Cvent taking this action to link this Passkey event/room block 
    1.  May or may not be a Passkey Manage User 
    2.  May or may not be a planner portal user 
    3.  May or may not be a planner portal user that is specifically assigned to the event being linked 
2.  The event they want to link may or may not be Reglink enabled

All scenarios to think through and define behavior for as we extend our reach to support this use case.  

## Requirements

### 10 - Navigating out of the Neighborhood Page Into Passkey \* 

1.  If a user authenticates into [planners.passkey.com](http://planners.passkey.com) from an Event Neighborhood page after the event has been properly linked, we need to:
    1.  Open a new window to the planner portal application
    2.  Authenticate the user into planner portal / Let them log in from emailed link OR username/password 
    3.  One logged in, they should be deep linked directly to the associated Passkey Event they were viewing in Cvent Core
    4.  If they don't have access that event, ideally they would be able see a treatment that denies them access to that event, and a way to navigate back to their planner portal Event List page.   This workflow is likely negotiable depending on cost though
    5.  Since a separate window, there shouldn't be a need to hyperlink them from planner portal application back to Cvent Core
2.  If a user authenticates into [manage.passkey.com](http://planners.passkey.com) from an Event Neighborhood page after the event has been properly linked, we need to:
    
    1.  Open a new window to [manage.passkey.com](http://manage.passkey.com)
    2.  If the Cvent User is
        1.  1.  already a linked MyCvent user to a Passkey account and is logged in, but does NOT have owner access to the linked event, bring them to their Organization page
            2.  Verify with UX - Do we need a treatment explaining to them why they aren't able to see the event owned by another organization?   
    3.  If the Cvent User is
        1.  not a linked MyCvent user to a Passkey account, but has a Passkey username/password - Allow them to log into Passkey? 
        2.  open Passkey in a new window ??  Could we still deeplink them to the linked Passkey event from the account they just came from?   
        3.  Or do we want to forego this use case and require users to properly be a linked via MyCvent user workflow if we allow them to deeplink into the Passkey app and event from Core? 
        4.  Negotiable depending on costs
