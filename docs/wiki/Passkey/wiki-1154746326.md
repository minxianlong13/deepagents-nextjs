# Objective

This wiki will be output of Cvent JIRAd1d78885-1a8e-3259-b68d-3df198ee3d46GROUP-127368, It aim to enable users to create a Passkey event by uploading a hotel contract PDF. The uploaded contract will be parsed by passkey-smart-room-assistant using Textract ( or fallback PDF extractions , Please refer to this [HIP wiki](https://wiki.cvent.com/spaces/PASKY/pages/862732777/Enhanced+Rooming+List+Processing)) , converted into an Event Metadata Object, reviewed by the user, and then submitted through the existing Event Request workflow used by Create Event from RoomList.

  

**Background**

As part of this work, we will reference sample hotel contracts [https://cvent.app.box.com/folder/385130917458](https://cvent.app.box.com/folder/385130917458) and the existing HIP implementation for creating an event from a contract:

## Current RoomList Flow

The existing Create Event from RoomList flow in passkey-rdk2 supports:

-   File upload for XLSX, CSV, and XLS
-   File upload service returns a fileId
-   Smart Room Assistant creates header auto-mappings
-   User reviews header mappings
-   User maps room types
-   Room list inventory summary is generated
-   Event Request Step Function creates the event

## Proposed Contract Flow

Create Event from Contract should reuse the same upload and Event Request infrastructure, but skip RoomList-specific spreadsheet mapping.

Proposed flow:

1.  User uploads hotel contract PDF
2.  File upload service returns fileId
3.  UI calls new Smart Room Assistant contract parsing endpoint
4.  Smart Room Assistant uses Textract to extract contract data ( or multi-fallback system to extract PDF contents -> ) 
5.  Parser returns an Event Metadata Object
6.  UI saves Contract Event Request with fileId and EMO
7.  User reviews and corrects extracted data
8.  UI submits updated EMO
9.  Event Request Step Function creates the event

## Key Design Gap

RoomList creates event data through spreadsheet mapping and inventory summary generation.

Contract creation should produce the EMO directly from the PDF parser.

This means Contract should likely be modeled as a separate request type instead of forcing it into the existing RoomList flow.

Recommendation:  
   
`RequestType.Contract`

# MVP Scope

## In Scope

-   PDF upload only
-   Contract parser endpoint
-   Textract extraction
-   EMO generation
-   Basic review and correction UI
-   Persist Contract Event Request
-   Trigger event creation from saved EMO

## Out of Scope for MVP

-   Hotel creation if hotel does not exist
-   Room type creation
-   Rate plan creation
-   Advanced template detection
-   User feedback loop for extraction improvement
-   Image upload support
-   Advanced AI prompt customization
